- **L-038**｜**把更正「附加」在被更正的那句話底下，而沒有改那句話本身**——004 U-M 實暴，且是同一刀內第三次撞上「同一假述有多份複本」的形。修第八態語意時，我在 spec FR-007 下方加了「★本值 **MUST NOT** 讀作『該請求未被服務』」，卻沒動它**正上方**那句定義句「標記『鏈跳數逾上界、**請求被拒**』」⇒ **同一條 FR 自相矛盾**，而且被禁的那個讀法就寫在最顯眼的字面列舉處（下游實作者查「這個字面什麼意思」的第一落點）。★**漏掉的機制很具體**：我的勘誤 grep 用的是自己剛寫的字面「未被服務」，而定義句寫的是**同義不同字面**的「請求被拒」——枚舉的關鍵詞取自**更正文**而非**被更正的概念**，於是自動漏掉所有換句話說的複本。審查輪 grep 的是 `請求被拒|未被服務|仍被服務` 整個同義集，一次抓到。★同批第二處＝`trust::Confidence::ChainRejected` 的 **rustdoc**（碼側的權威定義位）與其測試註解，兩份都還寫著舊語意——碼側定義位完全沒被那輪文件勘誤覆蓋。★**防法**：①**勘誤枚舉的關鍵詞取「概念的同義集」，不是自己剛寫的那個詞**——寫更正時順手列出「這個概念在 repo 裡可能被寫成哪幾種說法」再逐個 grep；②**更正一律就地改寫，不要只追加禁令**——追加只對「從頭讀完整段」的人有效，而多數人是搜到某一行就走；③**碼側的型別／變體 rustdoc 是定義的權威位**，文件面勘誤 MUST 同批掃 `src/**`，不能只掃 `specs/**` 與 `docs/**`；④驗收方式＝改完後用**同義集**再 grep 一次，命中應只剩禁令句與無關脈絡。 ★**收益已量化**（004 U-H 實證）：T037 把 `RUNTIME_APPEND_TABLES` 由三表擴為四表，review 只點名 `login.rs` **一處**；改以同義集（`恰 session_event`／`恰三表`／`三表）`／`RUNTIME_APPEND_TABLES`）全樹枚舉，抓出**四處**——多出的三處是 `model/mod.rs` 的守衛名冊 doc、`tasks.md` 給下一單元的移交註記（**我自己上一輪寫的**）、以及 ADR 0036（accepted、史料不動）。⇒「只修被點名那一處」在本 repo 的實測漏網率是 3/4。★與 L-032／L-033 的關係：那兩條講「跨檔複本」，本條講**同一份檔案內、緊鄰兩行**的複本——距離近不代表會被看到，反而因為「我剛改過這段」而更容易略過。
