- **L-041**｜**走查殘留不只在資料庫——Redis 節流計數與「還開著的登入分頁」同樣毒化下一次測試，且兩者都自毀證據**：004 U-I 走查後第一趟全量得 `server --lib` **399 passed／2 failed**，單獨跑 `-p server --lib` 卻 401 全過；關掉走查用的三個 CDP 分頁並再清一次表後，全量重跑 401 全綠且逐 target 與基線完全相同。★**成因未逐項定位**（失敗測試名未截下），但形狀與 L-031 同族且多出兩個載體：①**Redis 節流計數**——走查的登入探測會留下 L1 計數鍵，而現行 quickstart §1 收尾只清 **DB 三表**、完全不碰 redis；該層有 TTL ⇒ **第二趟就自己消失**，復現一次即無 ②**CDP 分頁**——走查開的登入態分頁會**持續打 API**（token 自動續期、輪詢），測試期間等於有一條你不知道的流量在寫 `sys_login_attempt`／推進 `last_activity`。兩者疊起來的外觀就是「重跑就綠」＝**誤判成 flaky 的成本很高**（會去找根本不存在的競態）。★**防法**：①跑全量 rust 前**先關掉走查分頁**（CDP 驅動的收尾步驟寫進去，不要只清表）②必要時連 redis 節流鍵一併清 ③**「重跑就綠」永遠先當成殘留、不要先當成 flaky**——L-031 的證據自毀機制與本條的 TTL 自毀機制會合謀讓你每次都只看到綠。★與 L-031 的分工：L-031 管 **DB committed 列**（證據被後續 cleanup 自毀），本條管 **DB 以外的載體**（Redis TTL 自毀、外部流量源）。
