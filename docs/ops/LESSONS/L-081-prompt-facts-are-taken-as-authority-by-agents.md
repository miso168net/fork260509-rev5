- **L-081**｜**寫進 agent prompt 的「事實接地」會被當成權威照著做，寫錯就是把錯誤規格化——而它看起來比 spec 更可信，因為是主線剛查過的口吻**：編排時為了省 agent 的探索成本，主線習慣把接地結果整段烤進 prompt（「授權矩陣＝Super 0000／Admin 5003／未認證 8888，皆統一信封、HTTP 200」）。這種句子在 agent 眼裡是已驗證的前提，它不會再去查；若主線是憑印象寫的，錯誤就直接進了測試斷言。★**2026-09-01 實暴**（008 之讀面裁判單元，**主線自身**）：上句的「皆 HTTP 200」是錯的——`rust-api/server/src/error.rs:137` 凍結的 13 碼矩陣逐字寫「HTTP status——例外恰二：4040→404、**5003→403**」。implementer 自行讀碼後**依碼不依摘要**，把 Admin 腿斷言成 `5003`＋HTTP 403 並在 report 明白指出「摘要該處與碼不符、已依『以讀碼為準』處置」——這次被接住了，但接住它的是 agent 的紀律，不是任何機器守。★**判別問句**：我寫進 prompt 的每一句事實，剛才是**查來的**還是**想起來的**？後者要嘛去查、要嘛標成「待你自行查證」。★**防法**：①事實接地段的每一條都附出處（檔:行 或 指令），沒出處的不寫②該段開頭明令「★本段與碼衝突時**以碼為準**，並在 report 指出哪一條錯」——把主線的錯誤變成 agent 會回報的東西，而不是它會照抄的東西③agent 回報「摘要與碼不符」時，主線 MUST 自己再查一次真源並把錯誤記下來（本條即該次記錄）。★**2026-09-02 補記（本刀三次復發、成因各異——防法①②有效但不足）**：同一刀內主線的事實接地連錯三條，每條的**錯法不同**，值得分開記：①**二手陳述過期**（U5）：把 BACKLOG B-125 條目「logout 必須經 app 打端」照抄進 prompt（方向還抄反了）——成因是引用了帳本而非碼，已另立 [[L-083-a-backlog-entrys-technical-premise-goes-stale]]。②**相對位置的基準沒講清楚**（U6）：寫「三個構造點的 `json!` 在第 3 行、後 2 行視窗不夠」，而實際 `json!` 落在**錨行後第 2 個** kept 行、既有視窗已涵蓋——我把「構造點第 3 行」（含錨行）當成「錨行後第 3 行」。★**凡描述相對位置，MUST 寫明基準含不含錨本身**（「錨行後第 N 行」而非「第 N 行」），否則讀者穩定地差一。③★**工具行為想當然，而該行為在 LESSONS 裡早有專條**（U7）：寫「產物四檔重算入口＝`pnpm gen-route`」，而 `sa gen-route` 是**互動腳手架、零寫檔**——這件事 [[L-053-gen-route-is-not-the-regenerator]] 的標題就寫著，`tools/route-artifact-gate.py` 檔頭亦逐字載明。防法①（附出處）擋不住它：我若真去附出處就會發現，但「跑個 gen-route 重算」讀起來太理所當然、根本不覺得需要查。⇒ **防法④（新增）**：事實接地段凡涉及**某個命令／工具會做什麼**（而非某個檔案裡寫著什麼），MUST 先 `grep` 一次 `docs/ops/LESSONS.md` 索引與該工具的檔頭——工具的**反直覺行為**正是 LESSONS 的主要住戶，碼裡查得到的是「它怎麼實作」，查不到的是「它不做你以為的那件事」。★三次皆由 implementer 依防法②回報並改述、零一次照抄落地——防法②是這三次唯一的實得防線。
