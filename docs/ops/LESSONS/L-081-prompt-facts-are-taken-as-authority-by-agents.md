- **L-081**｜**寫進 agent prompt 的「事實接地」會被當成權威照著做，寫錯就是把錯誤規格化——而它看起來比 spec 更可信，因為是主線剛查過的口吻**：編排時為了省 agent 的探索成本，主線習慣把接地結果整段烤進 prompt（「授權矩陣＝Super 0000／Admin 5003／未認證 8888，皆統一信封、HTTP 200」）。這種句子在 agent 眼裡是已驗證的前提，它不會再去查；若主線是憑印象寫的，錯誤就直接進了測試斷言。★**2026-09-01 實暴**（008 之讀面裁判單元，**主線自身**）：上句的「皆 HTTP 200」是錯的——`rust-api/server/src/error.rs:137` 凍結的 13 碼矩陣逐字寫「HTTP status——例外恰二：4040→404、**5003→403**」。implementer 自行讀碼後**依碼不依摘要**，把 Admin 腿斷言成 `5003`＋HTTP 403 並在 report 明白指出「摘要該處與碼不符、已依『以讀碼為準』處置」——這次被接住了，但接住它的是 agent 的紀律，不是任何機器守。★**判別問句**：我寫進 prompt 的每一句事實，剛才是**查來的**還是**想起來的**？後者要嘛去查、要嘛標成「待你自行查證」。★**防法**：①事實接地段的每一條都附出處（檔:行 或 指令），沒出處的不寫②該段開頭明令「★本段與碼衝突時**以碼為準**，並在 report 指出哪一條錯」——把主線的錯誤變成 agent 會回報的東西，而不是它會照抄的東西③agent 回報「摘要與碼不符」時，主線 MUST 自己再查一次真源並把錯誤記下來（本條即該次記錄）。
