- **L-046**｜**把「已知態」記成一個具體症狀時，記到的往往是最容易觀察的那條路徑，不是使用者實際會走的那條——依它寫的煙測／回歸守會驗一條沒人走的路**：004 收刀後 CDP 走查實暴。機制：B-008 與 ADR 0018 兩處逐字寫「manage_system-settings 等三項**點擊 404** 屬已知態」，ADR 0018 後果段並據此要求「前端煙測腳本須把該 4 項列為已知態、防誤判回歸」。★**實測兩條路徑症狀不同**：①**直接打網址**→ 確實是 404 頁（寫的人當時應該是這樣驗的——打網址最好驗）②**從側欄點該項**→ **零反應**，URL 不變、無 404 頁、無 console error、無 toast（前端 router 解析不到 seed 給的 `component`，導航被靜默中止）。而使用者只會走 ②。⇒ 以「點擊得到 404」為判準的煙測，**驗的是使用者根本到不了的狀態**：真的回歸了（例如某天連 404 都不給、或側欄項整個消失）它照樣綠。★連帶還漏了一個同源症狀：側欄顯示的是**未翻譯的原始 i18n key**（`route.manage_system-settings` 字面直接上畫面，因 `route:` 樹是窮舉型 `Record` 而該鍵不存在），兩份文件都沒記——**因為打網址那條路徑看不到側欄**。★**防法**：①記錄「已知態／已知缺陷」時 MUST 寫明**觀察路徑**（「打網址 → X」「點側欄 → Y」），只寫症狀不寫路徑＝下一位據以寫守門時必然選錯路徑；②**煙測的判準路徑 MUST 與使用者路徑同一條**——判準若取「最好自動化的那條」而非「使用者走的那條」，該守就是裝飾品；③一份不可變產物（ADR）記的 as-built 事實日後被實測推翻時，更正落在**該事實的活帳家**（本例＝B-008）並註明「以本條為準」，不是去改 ADR body（同憲法 v1.6.1 對 ADR 0043 的處置形）。
