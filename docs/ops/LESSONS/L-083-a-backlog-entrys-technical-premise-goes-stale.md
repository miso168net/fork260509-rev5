- **L-083**｜**BACKLOG 條目裡的技術前提會隨碼演化而過時，triage 沿用舊前提＝在錯誤基礎上反覆推遲**：待辦條目的典型結構是「因為碼現在是 X 形，所以做這件事要付 Y 代價 ⇒ 暫不做」。**結論**（暫不做）每次 triage 都會被重讀，**前提**（碼是 X 形）卻沒有人回去對碼復核——而前提正是整條論證的承重牆。★**2026-09-01 實暴（本刀 U5、B-125 關帳）**：B-125 逐字寫著「`detect_reuse` 是同模組私有 fn 可直呼，**logout 是收 extractor 的 handler、必須經 app 打端**」，並據此推出「要讓 app 跑在單連線 lock_timeout 池上得替它加一個收 db 的建構腿（或第三個 AppState 建構點——正是 B-054／B-101 兩批收攏壓下去的東西）」⇒ 判「代價與收益不成比例」。**實碼上這個前提是錯的**：`logout` 的四個 extractor（`State`／`Option<Extension<RequestContext>>`／`HeaderMap`／`Result<Json<LogoutReq>, JsonRejection>`）全部可直接構造，同刀 U4 的 `purge_tests` 早就在直呼同形 handler；而且**即使真要打端也走得通**——`model::test_db::oneshot_json_from` 的 doc 逐字寫著「★`ConnectInfo` **非手植不可**」，該 helper 送出前就手植了它。這條錯誤前提撐著該條目被推遲三次（2026-08-30 兩次 triage、一次觸發器改述），而真實成本是一個沿用 `test_state`、零新增 AppState 字面的薄殼。★**同一次還反向咬到主線自己**：寫本單元 agent prompt 時，主線把該前提**反向照抄**成「走 app 打端不可行（oneshot 不經 make-service ⇒ RequestContext 恆缺席）」——方向相反、同樣未經實碼復核；由 implementer 依碼糾正並改述（`[[L-081-prompt-facts-are-taken-as-authority-by-agents]]` 的「與碼衝突以碼為準並回報」明令生效）。★**為何特別難察**：條目愈長、triage 次數愈多，前提句愈像是「已經被驗過很多次的共識」；實際上被反覆閱讀的是**同一句從未復核的話**，重讀次數不產生任何證據。★**防法**：①凡條目或派工單出現「因為碼是 X，所以 Y 做不到／代價高」，動工或再次 triage 前 **MUST 對碼復核那一句 X**（復核的是**前提**，不是結論——結論讀起來總是合理的，因為它由前提推得）②寫條目時把**技術前提**與**價值判斷**分寫，前提句帶出處（`檔:行` 或指令），讓後人知道該去哪裡復核③關帳時把「條目哪一句與實碼不符」寫進收單訊息——條目本身完成即刪，這句話若不落在 git 史裡就永遠消失，下一個人會在別處重蹈同一個推論。★**一般化**：帳本條目的半衰期不是由它的年齡決定，而是由**它引用的碼面的變動速率**決定；引用愈具體的碼形，過期得愈快，而愈具體的引用又愈像是可信的事實。相關：[[L-081-prompt-facts-are-taken-as-authority-by-agents]]（同源）、[[L-032-historical-statements-stay-present-tense-gets-fixed]]（史述與現在式的分野——本條講的是「現在式的技術陳述過期後沒人發現」）。
