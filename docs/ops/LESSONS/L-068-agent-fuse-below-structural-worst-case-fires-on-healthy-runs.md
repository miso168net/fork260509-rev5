- **L-068**｜**Workflow 的 agent 保險絲若低於 script 的結構最壞值，它會在健康的 run 上開火——而且必定開在最後一支、最貴的那個時點**：本 repo 的單元編排 script 是固定形，每個審查 cycle 最多 `MAX_FIX_ROUNDS + 1` 支 review ＋ `MAX_FIX_ROUNDS` 支 fix ＝ **2·MAX_FIX_ROUNDS + 1**；兩個 cycle（規格符合性＋碼品質）＋ implementer 數即結構最壞值。`MAX_FIX_ROUNDS = 3` 時＝每 cycle 7 支、兩 cycle **14 支**，含兩支 implementer 的完整單元＝16、只跑審查的專跑＝**14**。★**2026-08-29 實暴**（本刀 U3 的審查專跑）：我手挑 `AGENT_FUSE = 12`，理由是「只跑審查、應該用得比較少」——**那個直覺與結構恰恰相反**（少掉的只有 implementer 那 2 支，cycle 一支不少），於是在第 13 支（碼品質 fix 第 3 輪）`throw`。★**開火位置是最壞的**：前 12 支的 token 全付了、三輪 findings 也都提出來了，卻卡在最後一輪 fix——要嘛主線接手補做（本次如此）、要嘛整個 cycle 重跑。★**根因不是值太小，是「手挑」**：CLAUDE.md 防呆③ 要求邊界寫死 script 常數、絕不取自 args（防的是「cap 與不可信輸入同源」），但沒規定**怎麼定值**；手挑就會與 `MAX_FIX_ROUNDS` 和 cycle 數脫鉤，改其中任一個都不會有人想到回頭調保險絲。★**防法＝由同一份 script 常數推導並自我斷言**（仍完全滿足「寫死 script、不取自 args」——推導源是同檔常數、不是外部輸入）：`const WORST = IMPLEMENTERS + CYCLES * (2 * MAX_FIX_ROUNDS + 1)`；`const AGENT_FUSE = Math.min(20, WORST + 1)`；`if (AGENT_FUSE < WORST) throw new Error(...)`。★**一般化**：安全邊界要**從它所守的那個東西推導出來**——太緊＝在健康路徑上開火（那是 noise，而且會訓練人去調高它、最後變成關掉它）；太鬆＝形同不存在。兩者都讓 backstop 失格，而「太緊」偽裝得比「太鬆」更好，因為它看起來像在盡責。相關：[[L-067-lint25-unit-round-shape-traps-current-generation-too]]（同族：機器守的判準要與被守物同源）。
