- **L-061**｜**base-web 的 `pnpm install`（含被 `pnpm typecheck` 在 node_modules 缺席時自動觸發的那次）會以其 `prepare` 腳本（simple-git-hooks）覆寫外層的 `.githooks-submodule/`——betterleaks 機密掃描整段消失、pre-push 被刪、多出一支 commit-msg；此後對任一子庫 commit ＝在掃描防線缺席下落 commit（CLAUDE.md §6 硬禁令）**：刀 B 前置維護批 U3（2026-08-25）的 implementer 跑 `pnpm typecheck` 時，base-web 的 `node_modules` 缺席 ⇒ pnpm 先跑了 6m24s 的 install，其 `prepare` 隨即改寫 hooks；agent 自己察覺並即時還原（`git show HEAD:.githooks-submodule/pre-commit > …`／`…pre-push > …`、`rm commit-msg`、`chmod +x`）後升級主線。★**這件事在 rev5 啟動書就被預見**（`docs/brainstorms/000-doc-architecture.md` Day 1 必到位清單第⑥項逐字寫著「bootstrap 一鍵體檢含 hooks 內容指紋斷言（**base-web 跑過 pnpm install 即覆寫 hooks，是 Day 1 已知拓樸事實**）」）——防線建了、指紋斷言也在 `tools/bootstrap.sh` 裡，缺的是**觸發時機**：bootstrap 是人工跑的一鍵體檢，沒有任何東西會在 pnpm install 之後自動叫它。★**危害為何隱蔽**：被換上的 pre-commit 本身「看起來很正常」（跑 typecheck／lint／fmt），commit 照樣會被擋或放行，唯一消失的是機密掃描與 pre-push——也就是說**失效方式是靜默的**，除非你去 diff hooks 檔本身。★**主線收尾複驗（可複用的驗法）**：①`git status --short -- .githooks .githooks-submodule` 須空 ②逐檔 `diff <(git show HEAD:<path>) <path>` 須逐位相同 ③檔案清單與 HEAD 一致（多出來的 commit-msg 屬未追蹤、`--untracked-files=all` 才看得到）④`git ls-files -s` 確認 exec bit 100755 ⑤`grep -c betterleaks .githooks*/pre-commit` 非零 ⑥`bash tools/bootstrap.sh` 全綠零警告。★**防法**：①任何跑過 base-web `pnpm install`／`pnpm typecheck`（node_modules 可能缺席）的單元，收尾第一件事是跑上述複驗或直接 `bash tools/bootstrap.sh` ②更根本的是讓它跑不動——`SKIP_SIMPLE_GIT_HOOKS=1` 環境變數，或在編排 script 的前端驗證命令前置該變數（改 `package.json` 屬 fork-delta 修改型、需授權判定，環境變數形不動檔） ③agent prompt 的前端驗證段應明載「node_modules 缺席時 pnpm 會先 install，install 會動外層 hooks，跑完必查」。
