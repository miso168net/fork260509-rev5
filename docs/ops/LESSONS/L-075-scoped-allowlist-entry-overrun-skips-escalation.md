- **L-075**｜**允許檔案清單裡的「限定式項」（檔在清單內、但只准改某一面）被越界時，agent 不會觸發 ④ 分值升級——因為它判「檔在清單內」就是沒越界**：防呆⑥把空間邊界定成**檔案清單**，而清單項寫成「`X.md`——★只准改 A、其餘一字不動」時，邊界其實有兩層（檔案級／改動面級）；agent 讀到的是「這個檔可以動」，於是改了 B 仍回 `status: ok`、`escalations: []`，主線若採信回報就完全看不到那批改動。★**2026-09-01 實暴**（008 修憲單元）：清單寫「SDD 三檔——只准改 rev4 大寫詞彙值 PURGE→purge 那四處、其餘一字不動」，implementer 另擴寫了 `tasks.md` 的 T004／T014／T024／T032 與 Dependencies 共五處，回報卻是 `status: ok`＋「零清單外檔案改動」。★**這一筆的內容是對的**——它填補了 ADR 0077 後果段承諾、而 tasks.md 無任一 task 承載的 L-063 防法②記派（真變異自證排進第一個落標記的實作單元），主線復核後採納；問題純在**分值誤判**，而分值誤判的代價是主線少了一次「該不該收」的判斷機會。★**判別問句**：清單項若含「只准改…／其餘不動」這類限定語，它就**不是**一個檔案級授權，而是一個改動面級授權；寫 prompt 時要把這件事講成 agent 聽得懂的分值語言，別假設它從限定語自行推出升級義務。★**防法**：①限定式清單項一律附一句「本檔之限定外改動＝清單外改動、依 status 分值升級（`done_with_escalation`）」②主線復核**不看 `escalations` 欄就下結論**——`git diff` 逐檔看實際改動面，限定式項尤其要看（`git diff -U0 <檔> | grep '^[-+]'` 即足）③agent 回 `status: ok` 不等於改動面在界內，那只是它自己的判斷。
