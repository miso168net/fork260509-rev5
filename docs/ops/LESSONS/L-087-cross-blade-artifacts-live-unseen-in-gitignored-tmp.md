- **L-087**｜**跨刀的可複用工件躺在 gitignored 的 `tmp/`，沒有任何機制會提醒你它存在——於是每一刀重新發明一次**：workflow 編排骨架、CDP 驅動 helper、量測腳本這類「跨刀複用件」在本 repo 的落點是 `tmp/`，而 `tmp/` 在 `.gitignore` 內 ⇒ **`git log` 搜不到、`git grep` 不經過、全 repo `grep -rn` 若限定在版控面也掃不到**；`docs-sync.py errata` 掃的是 `tracked_files(ROOT)`，同樣看不見它。⇒ 它的存在**只能靠「有人記得去列那個目錄」**。★**2026-09-02 實暴（008 刀 U9）**：CDP 三方對照要驅動瀏覽器，我在 scratchpad **現寫**了一支 `cdp.mjs`，匯出只有 `connect`／`sleep`。收刀執行 `tmp-clean`、逐項列清單時才發現——前代刀早就留了 `tmp/cdp9229/cdp.mjs`，**多出八個函式**（`listTargets`／`openTab`／`closeTab`／`findTab`／`evalIn`／`screenshot`〔含 `Page.bringToFront`〕／**`insertText`**／`clickByTextExpr`），而且**檔頭第二行就寫明**「慣例（memory `cdp-browser-driving`）：target 每步重解析、bringToFront 再截圖、innerText 點擊、**`Input.insertText` 打字**」。★**實害可指認、不是事後諸葛**：同一輪走查驗 SC-004 時，我用合成 `input`／`change` 事件去改 naive-ui 的受控數字欄——**沒被接住**（請求根本沒送出、庫值與 `updated_at` 皆未變），白跑一輪、還一度把它誤判成產品缺陷；最後改用 CDP 的 `Input.insertText` 真實鍵盤事件才成立——**那正是 `cdp9229` 已封裝好、且寫在檔頭第二行的那條慣例**。我不是不知道該用真實鍵盤事件，我是**不知道有人已經把它封裝好放在隔壁目錄**。★**為何特別難察**：①gitignored ⇒ 一切以版控面為基礎的搜尋（`git grep`／`errata`／PR diff）結構性看不見它②它不在任何規則、清單或索引裡——`CLAUDE.md` 不提、`README.md` 的目錄樹不含 `tmp/`、LESSONS 索引也沒有它的條目③**它看起來像暫存垃圾**（目錄名就叫 `tmp`），而暫存垃圾的直覺處置是「不用看、整包刪」。★**防法**：①動手寫任何**驅動件／量測件／編排骨架**之前，先 `ls -R tmp/`（或該類工件在本 repo 的既定落點）——成本一次 `ls`，省的是整輪重新發明②既有工件若比你要寫的完整，**用它、不要另寫一份退化版**；真要改良就改良那一份③`tmp-clean` MUST **列清單逐項判**（memory 協定已如此要求）——本條給該要求一個新理由：那目錄是跨刀資產庫，整包刪＝把資產和垃圾一起丟④新造這類工件時，在 `tmp/<名>/README.md` 或該檔檔頭寫明「這是什麼、給哪一類任務用」，讓下一刀 `ls` 到時看得懂。★**一般化**：**「被排除在主要索引之外」與「不存在」在搜尋行為上是同一件事**——凡是刻意排除在版控／索引／掃描面之外的東西（gitignored 目錄、`.local` 設定、被 `--exclude` 的路徑），它的可發現性就退化成「有人記得」；而「有人記得」在跨 session／跨刀的情境下等於零。相關：[[L-085-hand-rolled-grep-reinvents-a-worse-enumeration-surface]]（同上位、成因相反）、[[L-080-adding-a-file-is-itself-a-set-change]]（名冊釘看不見新檔——同樣是「掃描面沒涵蓋到」的形）。
