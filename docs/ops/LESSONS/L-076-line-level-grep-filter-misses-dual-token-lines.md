- **L-076**｜**枚舉同語意命中時用 `grep -v <不該改的 token>` 過濾整行，會漏掉「同一行同時含該改與不該改 token」的命中，且漏掉的那行看起來像根本不存在**：勘誤與改名類工作的標準動作是先枚舉再逐處處置，但枚舉結果常被順手用一條 `grep -v` 濾掉噪音；`grep` 的過濾單位是**行**，而同一行完全可能既有要改的字面、又有不能動的同前綴常數名 ⇒ 該行被整行丟棄，逐處處置從一開始就少了一處，且因為它不在清單上，復掃時也不會發現。★**2026-09-01 實暴**（008 修憲單元前置現算，主線自身）：枚舉 SDD 包待改對的 rev4 大寫詞彙值 `PURGE` 時用 `grep -rn PURGE … | grep -v PURGE_MIN_DAYS`，漏掉 `tasks.md` 的 T014 那行——它同時含常數名 `PURGE_MIN_DAYS`（大寫正確、不動）與詞彙值 `'PURGE'`（要改小寫）；四行三檔因此被誤數成三行，是拿另一份獨立枚舉對賬才發現的。★**判別問句**：「我要濾掉的 token，和我要找的 token，會不會出現在同一行？」——只要兩者共用前綴或屬同一術語家族（`X` 與 `X_MIN_DAYS`、`foo` 與 `foo_bar`），答案就是會。★**防法**：①**逐行剝 token 再判**，不整行過濾——`while read line; do stripped=${line//不該改的/}; echo "$stripped" | grep -q 目標 && echo "$line"; done`（或同形 python）②枚舉結果的**筆數**要有第二來源對賬（另一條不同寫法的指令、或既有文件記載的快照），單一指令的輸出不自證完整③改完的復掃用**同一條**逐處判別指令，不要換成更寬鬆的形。
