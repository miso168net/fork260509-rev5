- **L-057**｜**從既有單元 script 派生「只跑某階段」的續跑 script 時，刪掉 `IMPL_PROMPT` 會連帶把冒煙 token 一起刪掉——看門狗 ARMED 照出、`token(...)命中=0`，冒煙訊號整個失效而外觀與正常發射幾乎無異**：刀 B 前置維護批 U1（2026-08-25）於符合性階段升級主線（防呆⑥擋住清單外檔），碼品質輪從未跑過；主線依 L-027「需某階段重跑＝新開一支只跑該階段的 workflow」派生 U1b，作法是複製 U1 的 script 再刪去 `IMPL_PROMPT` 與 `phase('Implement')` 那一段。★**成因**：本代 script 定型把冒煙 token 寫在 implementer prompt 的**第一句**（「【…U1｜implementer（TDD）】冒煙＝PREB-U1-SMOKE-collapse。」），而 review／fix 的 prompt 從來沒有帶過它——冒煙 token 與階段耦合，一刪階段就蒸發。★**徵狀與誤讀風險**：看門狗照常 `ARMED`、`impl首行11186bytes` 也正常（第一支 agent 的 transcript 確實存在且有內容），**唯獨 `token(PREB-U1B-SMOKE-quality)命中=0`**；stall／runaway 兩道保險絲走目錄 mtime、完全不受影響 ⇒ 這**不是**發射失敗，也不會有任何後續告警提醒你——最容易的處置就是把它當誤報略過，而那正好把「證明第一支 worker 真的收到任務」這唯一一道證據丟掉（CLAUDE.md §9「Never fire-and-sleep：後即冒煙檢查」的檢查本身失效）。★**當次處置（可複用）**：主線改以手動補驗——`grep` 該 agent 的 transcript 找任務特徵句，命中「符合性**確認輪**」×1、「勿重報清單」×3、「797 passed」×2，且舊 token `PREB-U1-SMOKE-collapse` 零殘留（證明不是拿到舊 prompt），確認任務未失落後才續行。★**防法**：續跑／單階段 script 的**第一支 agent prompt 必自帶冒煙 token**；更穩的形是把 token 提到 `RULES` 或 `CONTEXT` 之類**所有 agent prompt 都會夾帶的共用段**，使它不隨任何階段被刪而蒸發——並可順帶讓 script 的渲染斷言（防呆②）像檢查 `zh-TW` 那樣一併斷言 token 字面在場，缺一即零派發。★**連帶**：派生型 script 的其它階段耦合物同理（例：`WORK_SCHEMA` 在 U1b 已無消費者卻仍留著——無害，但提醒派生時該逐項過一遍「這個常數還有人用嗎」）。
