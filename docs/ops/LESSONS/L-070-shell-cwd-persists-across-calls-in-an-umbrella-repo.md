- **L-070**｜**shell 的 working directory 跨工具呼叫持久化，在傘狀 repo 裡會把路徑錯誤偽裝成「檔案不見了」**：Bash 工具的 cwd 在呼叫之間**保留**，而 `cd` 是命令的副作用、不隨命令結束還原 ⇒ 一句 `cd rust-api && git log …` 之後，**後續每一個相對路徑指令都在子庫裡解析**。★**2026-08-30 實暴**（本刀 U10；同一 session 內兩次、加上更早的兩次共四次）：`ls ../fork260509-rev4/docs/…` 前一秒還成功，下一秒回 `No such file or directory`——因為中間插了一句 `cd rust-api`，`../fork260509-rev4` 於是解析成 `<repo根>/fork260509-rev4`（不存在）。同型的另一個面孔是外層指令回 `fatal: pathspec 'base-web' did not match any files`。★**危害在於錯誤訊息的措辭**：它描述的是「找不到」這個**結果**，從不描述「我在哪裡找」——於是 `ls ../fork260509-rev4/` 的失敗讀起來像「rev4 對照樹被人動過了」（而那是 CLAUDE.md §7 明列要停手問 user 的情形），`pathspec 'base-web'` 的失敗讀起來像「submodule 設定壞了」。**兩種誤讀都會把人帶往一條昂貴且完全錯誤的排查路**。★**傘狀 repo 放大了它**：單一 repo 裡 cwd 漂一層通常當場撞牆；本 repo 有兩個子庫 worktree ＋ 一個平行的 rev4 對照樹，相對路徑在不同 cwd 下**都能解析成某個看似合理的位置**，只是指向錯的東西。★**防法**：①子庫的 git 操作一律 `git -C <子庫> <cmd>`，**絕不** `cd <子庫>`（CLAUDE.md §3 的手冊已全用此形——本條補上它的理由）②非 git 指令若非在子庫內跑不可，用絕對路徑，或整句以 `cd <repo 根> && …` 起手，讓每一句自帶錨點③**任何路徑類錯誤，先 `pwd` 自證位置，再談對象存不存在**。★**一般化（與另兩條同族）**：診斷的第一步永遠是自證「我操作的確實是那個對象、在那個位置」——變異紅證「沒紅」有兩種成因（守門真 vacuous／變異沒打到那一格），CDP 走查「Admin 看到全部按鈕」有兩種成因（gating 真的失效／`clickByText` 用 `includes` 點到了「超級管理員」），路徑「找不到」也有兩種成因（東西真的不在／我在錯的地方找）。**三次都是後者，而三次的第一直覺都是前者。** 相關：[[L-069-visibility-widening-punches-through-a-roster-gate]]（同族：判準與被守物之間的距離）。
