- **L-058**｜**用自己想的 grep 樣式去驗「同語意失真已零殘留」，樣式比實際措辭窄就會漏改——而漏掉的那處往往就在同一個檔裡、與剛改好的句子直接矛盾**：刀 B 前置維護批 U1（2026-08-25）主線親修 `handler/common.rs` 之「ip_rule／role／menu **三域**」→「四域」（006 加入 policy_archive 呼叫端時未同步）後，以 `grep -rn "三域清單端點" rust-api/server/src` 驗零殘留、得零命中即收手。★**實暴**：同檔 `:331`（`MAX_CURRENT` 值釘測試的 doc）寫的是「服務 ip_rule／role／menu **三域**」——**沒有「清單端點」四字**，故不在樣式內；於是同一個檔裡 `:244` 說四域、`:331` 說三域，由 U1b 的符合性確認輪抓出。★**成因**：驗證樣式取自「我剛改的那句長什麼樣」，而不是「這個語意在 repo 裡有幾種寫法」——改動點自己成了樣式的來源，於是樣式必然只覆蓋改動點那一種措辭形。這是「用被驗證物當判準來源」的變形（同 ADR 0024 要求②之同源問題，只是搬到勘誤面）。★**正解本就在紀律裡**：CLAUDE.md §4 明文「勘誤：`tools/docs-sync.py errata <關鍵詞>` 機器枚舉全 repo 同語意命中、逐處處置後才 commit——**禁止只修被點名那一處**」；本次是主線知道該條而未執行、改用手擬 grep，等於把機器枚舉降級成人擬樣式。★**防法**：①任何「改一處措辭」的動作，收手前跑 `errata`，關鍵詞取**最短的語意核心**（此處＝`三域`，不是 `三域清單端點`）②自擬 grep 只可作為補充、且樣式必須是實際措辭們的**最短公共子串**③驗完把命中數寫進 report／commit message，讓「我驗過了」變成可覆核的數字而非宣稱。★**本次補跑結果**（作為形制示範）：`errata 三域` 0 命中；`errata N+1` 3 命中皆為史料（brainstorm／events append-only）與待刪的 BACKLOG 條目本身；`errata 首見序` 5 命中皆為待刪條目與 `specs/` 史料（禁動）。
