- **L-067**｜**Lint25 的「執行單元輪次」形連**本代**的「本刀 U2」都判紅，而最自然的兩個繞法各踩一個坑**：直覺以為 Lint25 只管**跨代**引用（條款名確實叫「跨代裸編號」、錯誤訊息也只建議「加 `rev4:`／`rev3:`／`rev2:` 前綴」），但其樣式 `("uround", "執行單元輪次", r"(?<!\d)(?P<uround>0\d{2}\s+U\d)(?!\d)")` 是**純字形比對、不分世代**——在 ops 帳本裡寫「本刀 U2 未自行發明新鍵」這種**指涉當前這把刀自己**的句子，照樣三筆 ERROR。★**2026-08-28 實暴**（本刀 U2 邊界落帳 B-136／B-137）：`docs-sync lint` 由 0 錯誤變 3 錯誤（BACKLOG.md 行 44／45），且因 pre-commit 會跑 lint ⇒ 單元收尾第⑥步的外層 commit 當場落不下去、得折返修文。★**第二個坑（更貴）**：把「本刀 U2」改成看似更完整的「**刀名全形＋空白＋U 輪次**」（例：`<三位刀號>-<刀名 slug> U2`）會躲開 `uround`，卻當場踩中同一條 Lint25 的另一個形 `("feat", "刀名全形", r"(?<!\d)(?P<feat>\d{3}-[a-z]+(?:-[a-z]+)*)")` ⇒ **錯誤數不減、只是換一種訊息**（本次由 fix agent 以 `importlib` 載入真 regex 逐串實測後指出，避免了第二次折返）。★**正解＝「本刀 U2」／「本刀 U1」**（零命中、可讀性最好，且與同檔既有條目的既存用法一致）；要保留刀號時寫 `rev5:本刀 U2`（前綴豁免，但囉嗦）。★**一般化**：ops 帳本（BACKLOG／LESSONS／NOTES）提及**任何**刀號或單元輪次前，先想一句「這串會不會被 Lint25 的某個字形樣式吃到」——判準不是「這是不是跨代引用」，而是「這串長得像不像那幾個 regex」；不確定就先 `python3 tools/docs-sync.py lint` 一次再落 commit（成本 13 秒，遠低於折返一輪審查）。相關：[[L-064-lint24-bizdata-match-arm-must-be-two-underscores]]（同族：機器閘看的是字形、不是意圖）。

★**尾註（本條自身即第三次實暴）**：撰寫本條的**索引行**時，標題裡逐字引用了那個違規字面，`docs-sync lint` 當場又紅一筆（`LESSONS.md` 索引行）——條目檔本體不在 Lint25 掃描面、索引行在。★★**而且我當時對成因的判讀是錯的**：以為「條目檔本體不在掃描面、只有索引行在」——真相是條目檔**在**掃描面，只是當下它還是 untracked（`??`），單跑 `docs-sync.py lint` 看不到它；**staged 之後 pre-commit 一跑就六筆紅**（三支新條目檔各自的本文），整顆外層 commit 被擋。⇒ ①**新建**的 ops 檔案要驗 lint，得先 `git add` 再跑（或直接讓 pre-commit 擋——但那是在 commit message 都寫好之後）；②引用違規字形時要嘛描述它（「刀號＋空白＋U 輪次」）、要嘛加 `rev5:` 前綴，**不要在掃描面內裸引**；這也是同族 Lint25 具名豁免（`docs-sync.self-corpus`／`adr0012.rule-example`）存在的理由——規則的示例文本天生會自撞。
