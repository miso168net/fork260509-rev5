- **L-085**｜**手拼 `grep -r --include=*.ext` 做全 repo 枚舉＝重新發明一個更差的枚舉面，而副檔名白名單會結構性漏掉「無副檔名的檔」**：`--include="*.md" --include="*.py" --include="*.ts"` 這種白名單讀起來像是「把該掃的都掃了」，但它以**副檔名**為准入條件 ⇒ **hooks／`Makefile`／`Dockerfile`／無副檔名的 shell 腳本一律不在掃描面內**。而這類檔恰恰是**描述閘與流程「現行契約」**的地方——它們最該被枚舉，卻最容易被過濾掉。★**2026-09-02 實暴（本刀 U8）**：`tools/seed-view-gate.py` 的 `EXEMPT` 由一列歸零後，我跑 L-032 跨檔假述枚舉，指令是 `grep -rnE "…" --include="*.md" --include="*.py" --include="*.sh" docs/ tools/ … .githooks/`——**範圍寫了 `.githooks/`、卻因 `.githooks/pre-commit` 無副檔名而完全沒進掃描面**，該檔的 seed-view-gate 說明段（當時逐字「具名豁免一列（B-008 餘一張 view）」）漏網。抓到它的是 workflow 的 fix agent（它用的是**不帶 `--include`** 的形），並在 escalations 裡逐字註明「★review 未抓到、由我自跑 L-032 枚舉補上（審查員的 grep 範圍未含 `.githooks/`）」。★**真正的教訓在下一層**：CLAUDE.md §4 的勘誤條**早就逐字指定了 `python3 tools/docs-sync.py errata <關鍵詞>`**，而該工具的掃描面是 `tracked_files(ROOT)`＝**git tracked 全檔**、與副檔名無關。事後實跑自證：`errata "具名豁免"` 在 `.githooks` **命中 3 處**——我漏掉的那一處，工具一開始就會給我。⇒ 我不是「枚舉技巧不夠好」，是**有現成工具不用、手拼了一個射程更窄的替代品**。★**為何會這樣**：手拼 grep 有「我控制得住範圍」的錯覺，而 `--include` 白名單看起來是在**增加**涵蓋（列了愈多副檔名愈像周全），實際上每多一個 `--include` 都是在**收窄**——它把「沒列到的一切」排除掉，包括那些你根本沒想到有副檔名這回事的檔。★**防法**：①L-032／L-038 類的全 repo 枚舉，**一律先跑 `python3 tools/docs-sync.py errata <詞>`**；手拼 `grep` 只用於 errata 之外的補充角度（例如需要正則交替、或要限定在單一子樹內逐行判別）②非手拼不可時，**用路徑範圍限定（`docs/ops tools .githooks`）而非副檔名白名單**——寧可多掃幾個二進位檔被 grep 跳過，也不要靜默漏檔③復掃驗收時**對照 errata 的命中數**，兩者差異就是你的枚舉面缺口。★**一般化**：凡是「白名單式的准入條件」（副檔名、目錄名冊、token 名冊）都有同一個性質——**列得愈多愈像周全，而漏的那個永遠不會發出聲音**。這與 [[L-080-adding-a-file-is-itself-a-set-change]]（名冊釘漏掉新檔）、[[L-010]] 族的「判準枚舉面窄於被判對象」是同一個形。相關：[[L-072-deleting-a-backlog-entry-without-sweeping-its-references]]（枚舉面選得對是這類工具的全部價值）、[[L-076]]（同一次枚舉裡的另一種漏法：整行過濾吃掉同行雙 token）。
