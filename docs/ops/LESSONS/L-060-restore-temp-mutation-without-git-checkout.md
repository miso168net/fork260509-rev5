- **L-060**｜**落地紅證的「暫改真檔→驗紅→還原」，還原絕不可用 `git checkout -- <檔>`：checkout 的射程是「整個檔的全部未 commit 改動」，而暫改的射程是「一處」，兩者不相等——安全與否取決於當下工作樹狀態，而執行者（尤其 agent）無法可靠判斷**：刀 B 前置維護批 U2（2026-08-25）的 implementer 在做 B-111 落地紅證時，暫拔 `server/src/handler/role.rs` 的一個守衛屬性驗紅，**還原時用了 `git -C rust-api checkout -- server/src/handler/role.rs`**，違反烤進 script 的不可違反項「絕不 git checkout」；它自己在 report 裡誠實自陳（★這種自陳是高價值訊號，同 L-056 的連帶心得），後兩處暫改（`main.rs` serve 行、`config.rs` 判別式）即改以「python 存原文→寫回」還原。★**本次無實質損害純屬狀態使然**：`role.rs` 當時零未 commit 改動（U1 已於 `6ee82e2` 收單），checkout 的效果恰好等於還原那一處。★**但該檔正在 U2 的允許清單內**，且拍板明寫「B-111 lint 掃出真違規時補 `#[serde(serialize_with = …)]` 屬性」——若當輪真的補過，那一補會被同一句 checkout 一併抹掉；被抹掉的若是受 lint 管的屬性還會紅，若是 doc 改寫或註解就**完全靜默**。★**防法**：①暫改還原一律「存原文→寫回」（`cp` 備份或 python 讀寫皆可），還原後以 `git diff --stat`／`--name-only` 證零殘留 ②script 的 git 禁令保持「絕不 checkout」，並補一句替代作法——只寫禁令而不給替代路徑時，agent 會在「我需要還原」的當下自行發明手段 ③主線自己也照辦：本單元主線做兩次變異測試（改 `SECTION_QUOTAS[5]`、拔 `UserInfo.user_id` 的 `as_string`）皆用備份檔還原並以 `git -C rust-api diff --name-only` 逐次確認未列該檔。
