- B-074｜IPv4-mapped IPv6 **網段字面**在信任模型設定面靜默失效：`trust::in_set`（`rust-api/server/src/trust/mod.rs`）只對**查詢側 IP** 過 `to_canonical`、**不折疊網段字面**，而 `config::parse_cidrs` 也原樣收下 ⇒ 維運若把某段寫成 `::ffff:10.0.0.0/104`，解析成功、**零告警**，但 `contains(10.0.0.5)` 恆 false、該集合永不命中（004 U-B 品質審查輪於容器內以 ipnetwork 0.20 實測確認）。方向為 **fail-safe**（只縮小信任、不會誤放行），故當時未列 blocker。★兩條候選處置：①載入面於 `parse_cidrs` 折疊 mapped 網段字面 ②載入面偵測到 mapped 形即發結構化告警並清空該集合（與三層語意的第③層同形）——後者較誠實：mapped 網段語意本就罕見，與其猜維運意圖不如讓他知道。★連帶已知態：在此之前，「設定寫了卻不生效」這個症狀在 mapped 形下無任何訊號可循｜下一把動信任模型載入面或 `trust::in_set` 的刀，或維運回報「設定寫了卻不生效」時

- B-076｜門鈴 `cache::publish` 的回傳值（**訂閱者數**）在生產面**零消費者**：`ipgate::reload_and_publish` 只接 `Err`、把 `Ok(n)` 整個丟棄，而該原語的 doc 逐字寫著「回傳值刻意不吞成 `()`……吞掉即永遠問不出來」——生產面實際上就是沒有任何人問。★**單副本下無害且刻意**（ADR 0014 決策 4 拍板單副本 ⇒ 健康態恆有本行程 watcher 這一個訂閱者、回 `Ok(1)`；`Ok(0)` 只出現在 boot 到訂閱成功、退避窗、訂閱失敗／逾時三種狀態，而這三種watcher 自己都已各發過一則 `doorbell` 降級，在此再發即與真實故障次數對不起來；data-model §5 亦無「零訂閱者」列）。★**觸發後的危害**：若日後拍板多副本，`Ok(0)` 的語意就從「本機還沒訂上」變成**「全部副本的 watcher 都失聯」**——那是規則改了但**整個叢集**都不生效的形，而現行**零訊號**。屆時須連同「`publish` 回 0 是否計降級」「是否需要訂閱者數的下界告警」一併重審。（004 U-G 規格確認輪列為誠實界線、明文建議落帳）｜拍板多副本部署時，或 ADR 0014 的單副本決策被翻案時

- B-078｜**「稽核欄含 `real_ip`」的字串包含式複驗，在 IPv6 非正規化字面下假陰性**：`trust::rightmost_window_str` **逐字保留**鏈欄原文（刻意——不可解析欄是鑑識痕跡），而 `real_ip` 是 `to_canonical(..).to_string()` 的**壓縮小寫**形 ⇒ 鏈裡寫 `2001:0DB8:0000:0000:0000:0000:0000:0009` 或 `2001:DB8::9` 時，`real_ip` 落 `2001:db8::9`，`x_forwarded_for LIKE '%'||real_ip||'%'` 得 `f`。★**方向是假陰性**（該跳其實**仍在窗內**、以同一份取窗＋正規化重推得同一結論），故憲法 F8 的條文本身**不失準**——F8 講的複驗是「重推」不是「字串包含」。★**危害觸發點**＝有人把 quickstart §1b 的 `LIKE` 判別搬進正式稽核報表、對賬腳本或機器閘：屆時合法的 IPv6 來源會被系統性報成「稽核欄不含真實來源」＝憑空製造一批假的鑑識缺口告警。★**不受影響的形**：帶埠 `1.2.3.4:5678`、帶區域 `fe80::5%wlan0`、方括號包裹者，正規化後仍為原字串的子字串。★候選處置：①複驗一律走「重推」路徑（讀鏈欄→`normalize_xff`→`resolve_client_ip`→比位址值），別用字串包含 ②若非要字串比對，先把鏈欄逐欄正規化再比（但那會丟掉逐字痕跡、與 `rightmost_window_str` 的刻意設計相抵）。（004 U-M 規格確認輪列為 notes 級、明文建議落帳）｜有人要把稽核欄複驗寫進報表／機器閘時，或稽核管理頁刀
