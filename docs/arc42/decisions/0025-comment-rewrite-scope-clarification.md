## 背景

憲法 §I.5 的前代 source 立場清單含「註解一律重寫」款：不拷前代註解；rev5 語境重寫
（引 rev5 契約／ADR）、前代出處帶 `rev4:` 前綴（ADR 0019）。002-system-settings 各單元
review 反覆撞同一爭點：**測試斷言訊息字串與 rev4 逐字相同，是否違反該款？**

主線判定（2026-08-08）＝**不違反**。該判定當時已烤進各單元 review prompt 壓住重報，但
每把 rust 刀都會重新遇到——B-046 開帳要求比照 ADR 0021 的釋義形立 ADR 定形。本檔即該
落檔：釋義而不修憲，§I.5 條文本體零改動。

## 決定

1. **判定**：測試碼中的**執行期診斷字串**——assert 巨集的訊息引數，及同類的 `panic!`／
   `expect`／`unwrap_or_else` 等說明引數（B-046 爭點原形為 assert 訊息；同一批測試檔中
   這些形在語意上完全同類，一體適用）——與 rev4 逐字相同**不違反**
   §I.5「註解一律重寫」款。理由有二：
   - (a) 條文明寫「不拷前代**註解**」——這類診斷字串是**碼**不是註解：它們是表達式的
     一部分、隨測試執行進入斷言／panic 輸出，不是原始碼旁的說明文字。
   - (b) ADR 0019 §2 要的是「重新打字消化、不可整段複製」，而描述同一契約事實的短中文句
     重打之後必然高度相似——為了不同而改寫屬「為改而改」，不增加任何消化度。
2. **真正在射程內的**（本款照常全力適用）：
   - **會送上 wire／log 的診斷字串**——那些是產品面文字，須為 rev5 語境（引 rev5 契約／
     ADR，不得原樣沿用 rev4 措辭中已被 rev5 拍板推翻的語意）；
   - **doc comment／行註解本身**——§I.5 字面所指：一律 rev5 語境重寫，rev4 出處帶
     `rev4:` 前綴。

## 後果

- 後續 rust 刀的 review 不再重報「**測試碼中的**執行期診斷字串（assert／`panic!`／
  `expect`／`unwrap_or_else` 訊息）與 rev4 逐字相同」型 findings；引用權威＝本檔（不再
  依賴烤進 review prompt 的臨時壓制）。產品碼中的同類字串會落 log／stderr，屬「決定」2
  的射程內對象、不在本免報範圍。
- 本檔為釋義、零修憲：§I.5 拷貝禁止（重打字消化）與防回歸條款的強度不因此放寬——
  這類診斷字串同樣須經重打字，只是「重打後恰好逐字相同」不構成違規。
- 若日後要把 wire／log 診斷字串的 rev5 語境要求做成機器閘，或要收緊／放寬本釋義的界線，
  那是新拍板、走新 ADR。
