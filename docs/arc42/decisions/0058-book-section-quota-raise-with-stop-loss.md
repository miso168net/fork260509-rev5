## 背景

`tools/docs-sync.py` 的 Lint07 除檔案預算（行數／token）外，另設**活書單節配額**
（常數 `SECTION_QUOTAS`，十二節逐節一值）；超出**只報警告、不擋 commit**。

2026-08-25 量測（取得指令＝`python3 tools/docs-sync.py lint`，尾行「活書各節行數：…」逐節照抄；
配額欄同取自該行斜線右側）：

| 節 | 行數 | 改前配額 | 改後配額 |
|---|---|---|---|
| §1 簡介與目標 | 15 | 40 | 40 |
| §2 約束 | 15 | 30 | 30 |
| §3 脈絡與範圍 | 3 | 50 | 50 |
| §4 解決方案策略 | 15 | 40 | 40 |
| §5 建構塊視圖 | 85 | 90 | 90 |
| **§6 Runtime** | **120** | **120** | **160** |
| §7 部署 | 3 | 60 | 60 |
| **§8 橫切概念** | **89** | **90** | **130** |
| §9 架構決策 | 4 | 5 | 5 |
| §10 品質需求 | 3 | 40 | 40 |
| §11 風險與技術債 | 3 | 3 | 3 |
| §12 詞彙 | 11 | 30 | 30 |

★**警告級的漂移為何有害**：配額超出不擋 commit ⇒ 它不會逼任何人處理，只會讓「lint 全綠」
這個日常判準從「0 錯誤 2 警告」漂成「0 錯誤 3 警告」（該二警告為與本題無關的 Lint11 詞典
命中，2026-08-25 量測同一指令末行「lint：0 錯誤／2 警告」）。漂移之後，下一位覆核者看到
三則警告時**無從分辨哪一則是本刀新增的**——守門的訊號被自己的雜訊淹掉。006-authz-governance
收刀時即實遇此形：§6 只做 errata 字面替換（零行增減）以避開觸頂，屬回壓而非解決。

## 決定

1. **兩節配額新值**：`SECTION_QUOTAS` 之 `6: 120` → `6: 160`、`8: 90` → `8: 130`。
2. **其餘十節一個字不動**（§1 40／§2 30／§3 50／§4 40／§5 90／§7 60／§9 5／§10 40／
   §11 3／§12 30）——本決定的射程恰為上述兩節，不是「配額整體太緊」的通盤放寬。
3. **停損條款（逐字）**：**下次再撞頂不再調高**，改走「as-built 下放」——把該節部分
   as-built 下放到**碼註**或**新建之獨立文件**，活書只留指針。★下放去處**不得是
   `specs/*/contracts/`**：全 repo 的 contracts 目錄只存在於 `specs/` 下（2026-08-25 量測，
   取得指令＝`find . -name contracts -type d`，六筆全在 specs），而該樹是已收刀史料、
   不可改（見替代案①）——把現在式 as-built 放進過去式的家是死路。本 ADR 是這兩節配額的
   **最後一次**放寬。
   ★**停損不只是承諾、算術上亦已無空間**（2026-08-25 量測）：`SECTION_QUOTAS` 總和自 598
   升至 **678**，加 `ARCHITECTURE.md` 的結構行（十二個節標題＋front-matter，現 12＋5＝**17**）
   ＝最壞情形 **695**；而 Lint07 對該檔的**檔案預算**是 **700 行 ERROR**（`BUDGETS` 表，
   非警告級）。取得指令＝`python3 -c "…sum(SECTION_QUOTAS.values())"` 與 `wc -l
   docs/arc42/ARCHITECTURE.md`。也就是說「再放寬一次」必然撞上檔案級硬擋——警告級的
   單節配額用完之後，接手的是會擋 commit 的那一道。
4. **停損之機器承載＝釘值測**：`docs-sync.py` 自測區新增 `test_section_quotas_pinned_by_adr`，
   ★斷言**整張 `SECTION_QUOTAS` 表恰等**（非只釘 6／8 兩鍵）——§6／§8 因款 1 之放寬而釘、
   其餘十節因款 2「一個字不動」而釘，兩者由同一支測承載。★它**不是正確性守衛**、不防止
   任何錯誤——它是**絆線**：讓下一個想調高**任一節**配額的人**必須動到它**，從而在改測的
   當下看見本 ADR 的停損條款（★因此 §5 這個最緊的節也在絆線內，見下節）。常數區上方另補
   一句註解指回本 ADR（人讀面的同一指針）。

## 為何是 §6／§8 而非別節

此二節是設計上**每刀都會長 as-built** 的兩節：

- **§6 Runtime**＝各刀的行為序 as-built（信任錨與 IP 存取閘判定序、會話狀態機、登入失敗
  節流三區…）。每把動到 runtime 行為的刀都在此節增列，而凍結面留在 constitution、
  活書承接的正是「會隨實作長」的那一半。
- **§8 橫切概念**＝fork-delta 接線現況（每個 UI 刀新增一條 ★軌道用途）＋資料／API／授權
  三組慣例。前者的成長與前端刀數同步，後者隨授權能力面擴張。

★**本 ADR 不宣稱「其餘十節穩定」——§5 是已知的同型逼近、屬本 ADR 射程外**：§5 建構塊視圖
2026-08-25 量測 **85/90**（餘裕 5 行，為全表最緊者），且逐刀增長——取得指令＝
`for r in 1fbc7ba b4fca6a 5291adc 512ede9 65eaa32 cbc5ba4 HEAD; do git show $r:docs/arc42/ARCHITECTURE.md | awk '/^## §5 /{f=1;n=0;next} /^## §/{if(f){print n;f=0}} f{n++} END{if(f)print n}'; done`
（2026-08-25 執行 → 3／13／35／61／70／75／85，逐段增幅 +10／+22／+26／+9／+5／+10；末一段
發生於維護批而非 feature 刀）。之所以仍不併入本次放寬：主線拍板的射程即為 §6／§8 兩節，
§5 該不該放寬需要自己的量測與權衡，另案處理（B-083 三候選同適用）。
★**§5 仍在絆線內、但不在放寬內**（誠實界線）：款 4 的釘值測釘整張表 ⇒ 日後撞 §5 頂而改
`SECTION_QUOTAS[5]` 的人**會**被絆到、會讀到本 ADR 的停損條款；但本 ADR **未替 §5 做任何
權衡**，其配額該不該動、動多少，需要該次自己的量測與拍板（B-083 三候選同適用）。

★量測佐證（2026-08-24 立帳之凍結量，取自 B-083 條目）：005→006 使 §8 由 **77→89**
（+12 行／刀）。以此速率，§8 之 +40 約當 **3～4 刀**餘裕。
★**§6 的自然速率無從量測，其 +40 可能不足一刀**——不把 §8 的速率外推到 §6：§6 自 004
觸頂後即受回壓（005／006／維護批皆 +0 行，屬回壓而非解決），唯二未受壓抑的增幅為
**+48**（003 建節，3→51）與 **+66**（004，54→120）。取得指令＝
`for r in bc05d0a^ bc05d0a ae6b656^ ae6b656 HEAD; do git show $r:docs/arc42/ARCHITECTURE.md | awk '/^## §6 /{f=1;n=0;next} /^## §/{if(f){print n;f=0}} f{n++} END{if(f)print n}'; done`
（2026-08-25 執行 → 3／51／54／120／120）。故本 ADR **不對 §6 承諾任何刀數餘裕**；一把
runtime 行為面重的刀就可能吃掉 +40 而當場觸發停損。接受此風險的理由：停損正解已於款 3
寫定，觸發時該做什麼是確定的。
★以上推估為凍結量、標明時點：日後刀的實際增幅不重算本段。

## 考慮過的替代案

- **①把 §6／§8 依子系統拆節**（B-083 候選①）：不採。拆節動的是 arc42 節號骨架，全 repo
  對 §6／§8 的既有引用須逐處重定向；且 `specs/` 是**已收刀的過程史料、不可改**（過去式歸
  git），其內的 §6／§8 指涉會自此永久失準——修不了也不能修。★引用面規模＝2026-08-25 量測
  （取得指令＝`grep -rIl --exclude-dir=node_modules --exclude-dir=target --exclude-dir=.git
  "§6" docs specs CLAUDE.md README.md rust-api/server/src base-web/src | wc -l`，§8 同形替換
  關鍵詞）：含 `§6` 者 **75** 檔、含 `§8` 者 **47** 檔（凍結量、2026-08-25 時點）——★此二數
  **含本檔**：本檔恆含 `§6`／`§8` 字面且 accepted 後不可變，故本檔對此二數的 **+1 是永久的**
  （落地前同指令為 74／46）；總數則隨他檔增減續漂（每把刀新增的 specs／docs／reviews 皆會抬高），
  日後不重算本段。
- **②把 §8 的 fork-delta 接線段下放獨立文件**（B-083 候選③之一形）：**不是不採，是列為
  停損後的正解**。該段 2026-08-25 量測 **45** 行（取得指令＝`awk '/^### fork-delta 接線現況/,
  /^### 資料慣例/' docs/arc42/ARCHITECTURE.md | head -n -1 | wc -l`），且每個 UI 刀都長；搬出
  可令 §8 立刻回到約半額。之所以現在不做：成本含 Lint07 檔案預算表新列＋README 文件地圖
  新節點＋逐一檢查引用該段者，是一件有自己風險面的搬遷工項；且**它解不了 §6**——§6 觸頂
  是本題的觸發點，只搬 §8 等於下一刀照樣撞牆。★另有一條**非工項成本**：下放後活書不再是該段
  as-built 的家、只剩指針，與 B-083 對此候選記下的「活書＝現在式 as-built 單一家」取態相抵——
  停損觸發時需連同此取態一併重審。停損條款把此案排在下一次撞頂時執行。
- **③逐刀壓縮既有內容**：不採。零結構變更、看似最省，但 §8 密度已高（現況即為多層縮排的
  逐條 as-built），006 收刀對 §6 已壓過一輪；再壓一輪的結果是下一刀又要再壓——把治理成本
  攤成每刀的固定稅，不可持續，且壓縮本身有損 as-built 的可讀性。

## 後果

- **配額的「牙齒」被放寬了一次**——誠實寫出這一點：本決定沒有讓兩節變得更精簡，只是把
  容許值往上推。它換到的是「判準恢復基線意義」（lint 全綠＝0 錯誤 2 警告，新增警告即為
  本刀引入）與「下一刀寫 as-built 時不必為避開警告而扭曲內容」。★此效力**不覆蓋 §5**
  （2026-08-25 量測 85/90，見上節）：§5 撞頂仍會令同一判準再次漂移——只是改其配額的人
  會被釘值測絆到、讀到停損條款。
- 下次撞頂時，釘值測會逼改動者動到 `test_section_quotas_pinned_by_adr`，從而看見本 ADR
  的停損條款——這是本決定唯一的機器承載。其效力**止於「讓人看見」、不及於強制**（改動者
  可以連測一起改）；惟門檻高於自願：`.githooks/pre-commit` 對 staged 的納冊工具跑
  `python3 <工具> test`，而調配額必然 staged `tools/docs-sync.py` ⇒ 絆線在 commit 當下硬擋，
  不靠人記得跑自測。
- **零內容變動**：不影響任何既有活書內容、零行搬移、零 lint 條款新增、零工具名冊變動。
  改動面＝`docs-sync.py` 的 `SECTION_QUOTAS` 常數區（含其上方註解）與自測區一支新測。
- 自測案數 +1；`docs-sync.py lint` 的錯誤／警告數不變（2026-08-25 改動前後同為
  0 錯誤／2 警告）。
