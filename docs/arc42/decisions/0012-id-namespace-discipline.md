## 背景

repo 大量內容移植自前代（rev4 為主、部分 rev3／rev2 血緣），註解與文檔帶著前代編號空間的
裸編號（刀號、ADR、L-NNN、B-NNN、T-NNN、FR/SC、契約條款 PN.N 等 19 族），與 rev5 原生
同形編號無法從字面區分。三個實證使本紀律成為必要而非潔癖：

1. **撞號已真實發生**：nginx 設定內的裸 B-037（rev4 指涉）與 rev5 已配號 B-037
   （bash→python 轉換批③）同號不同義；compose 檔的裸 001 刀名對撞 rev5 原生 001 刀。
2. **污染持續發生**：審計基準前兩個 commit 即新引入 7 筆裸前代編號——其中一行自身正在
   書寫「rev5 增補 vs 前代契約」的區分卻仍寫裸號。寫的人有完整脈絡仍會漏，人工紀律擋不住。
3. **散文限定擋不住擴散**：同一 ADR 檔內首處用空格散文限定形、後兩處即退化純裸；
   跨檔並列前綴（同號在甲檔有前綴、乙檔裸寫）亦已實證。

## 決定

1. **前綴依血緣**：rev4 指涉→`rev4:`、rev3→`rev3:`、rev2→`rev2:`。絕不以「大多數是 rev4」
   一律套 rev4:——那是用新錯誤換舊模糊（前代各代同號不同刀）。
2. **裸刀號只加前綴**（例：裸刀號→`rev4:019`），不強制展開刀名全形；前代刀內重號的殘餘
   歧義為已知並接受的代價（user 拍板、推翻展開全形之建議案）。
3. **逐 token 帶前綴才合規**：並列形一律逐 token（`rev4:ADR 0080／rev4:ADR 0084`、
   `rev4:L-129／rev4:L-143`）；空格散文形（`rev4 P1.1`）與共享前綴形不算合規。
   機器口徑因此可用單一 regex 判定、零上下文依賴。
4. **自測 fixture 用明顯假號段**：B-9xx／L-9xx／999-fake-slug 族，永不落入 rev5 可達
   號段；既有擬真假號（含已與現存條目同號者）隨清償刀遷移。
5. **帳本例外**：LESSONS 可就地**勘誤級**修字（不動條目編號／順序／語意）；
   events.jsonl 既有列**絕不編輯**、澄清只能 append 新事件。
6. **已收刀 spec 可動**，限前綴化與消歧註記、不改規格語意；存證引用（句子主詞即被清償
   字面者）具名豁免。
7. **防復發閘＝新 lint 條款（暫名 Lint25，配號依現行上界推進）**，與清償**同刀**落地：
   WARN＋DAY1 具名豁免（帶解除謂詞）起手、清償完成轉 ERROR。樣式集以審計 19 族全表
   起手、判定基準掃源現算（rev5 registry：specs 目錄名／ADR 檔名／LESSONS 與 BACKLOG
   next-id）、絕不落字面名冊。白名單四類：Lint11 負向樣本、grafana uid 內嵌刀號字面、
   vendored 面（.specify／.claude/skills／sea-orm-adapter）、規則反例 mention
   （如 ADR 0004 內引用之舊 lint 名）。已知極限：號段判定對「號落原生區間、語意屬前代」
   的遮蔽型殘留無效（審計實見 5 筆）、靠人工審查兜底。

## 後果

- 施工承載＝B-004（射程已改寫為 19 族／批次 A~J／首個維護批）；本 ADR 只記口徑、不含
  逐筆清單（逐筆判定資料屬 gitignored 工作資料、不入版控不被引用）。
- vendored 禁改面（sea-orm-adapter 之 rev2 編號）以檔頭 provenance 或聲明處理、
  永不動檔內字面。
- 本紀律對未來世代同構適用：rev6 起以 `rev5:` 前綴引用本代編號，判定 registry 換代重算。
