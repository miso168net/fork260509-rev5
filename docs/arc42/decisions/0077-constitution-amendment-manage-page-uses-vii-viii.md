## 背景

008-audit-settings-pages 撞到**兩個凍結位**，皆為憲法自身備有的授權路徑、非違規待辯護：

   （`manage_system-settings`／`manage_audit`）做成真功能，其 route 標題鍵與頁面文案鍵位於
   兩語 locale 之 `route:`／`page:` 兩樹、`page:` 為顯式型樹故 `src/typings/app.d.ts` 的型節

   (i)～(vi) 分別授權 IP 規則頁進場／role·menu 頁 CRUD 接真／三顆授權 modal 接真／
   policy-archive 頁進場／user 管理頁接真／個人中心改密頁，**涵蓋不到**本刀兩頁 ⇒ 依
   「同軌道內的未列用途不自動授權」須 Amendment 加兩用途。本刀屬**頁進場型**（新 route 鍵＋
   新 page 節＋新 view 檔＝「面」級新增、不適用補完判準），形照先例 (i)／(iv)，**不是**
   (ii)(iii)(v) 那種既有頁接真型。
2. **§I.7 行為島候選＝稽核域**——rev4 曾入憲十座行為島 A～J，rev5 現況九座（A～I）、

**寫法取捨三筆（回報備查）**：

- **產物四檔沿 (iv) 之「授權沿 (i) 列、本列不重複列名」形，本列不逐支寫出路徑**：兩形皆有
  先例——(i)（v1.4.0 舊列）逐支寫出、(iv)（v1.8.0）交叉引用。本案取 (iv) 形，三筆反面事實
  壓過「路徑落字較強」之直覺，逐筆列出如下（T003 已於 2026-09-01 逐筆過目、核可本形）：
  ①**憲法 §III 正文自身反對**：生成檔紀律（ADR 0052 條款、v1.8.0 納入正文）逐字＝「……與
  §III.2 表內『路由外掛產物四檔』同族——由工具重算產出、**禁手改**、不逐行標記、**不入任何
  用途之檔級名單**」；而表外宣告 1 逐字把範圍欄定義為檔級名單（「**檔級名單則是硬邊界**——
  名單外的 base-web 既有檔一律無授權」）⇒ 把四支生成檔逐支寫進 (vii)(viii) 範圍欄，字面上
  即是把它們放進兩個用途的檔級名單；落字後憲法與該條款字面相牴之處將由現況 **1 處**（(i)
  舊列）變成 **3 處**。
  ②**先例的時序方向**：(iv) 與該生成檔條款**同批**於 v1.8.0 入憲（憲法 1.8.0 log 條目逐字
  含「＋§III 正文納 ADR 0052 生成檔條款」），即該條款生效後所建立的規範形恰是「不重複列名」；
  (i) 是 v1.4.0 舊列、早於該條款，屬條款生效前的遺留形。
  ③**機器面零增益、且會多一份可漂移鏡像**：`tools/route-artifact-gate.py` 之
  `TRACK_PURPOSE = "(i)"` 為寫死常數、`cmd_check` 以 `parse_roster_row(text)` 走該預設 ⇒ 該閘
  **只讀 (i) 列**；(vii)(viii) 若各列一份路徑清單，無任何機器讀取者，與 (i) 一旦漂移零偵測。
  此與下一筆取捨（紀律欄不照抄，理由逐字「照抄一次就多一份會漂移的鏡像」）同一理由，兩筆
  方向因此一致。
  ★**另一形＝逐支寫出路徑**（草案未採；T003 已親決維持沿 (iv) 交叉引用形）：其論據＝表外宣告 1 之「檔級名單為硬
  邊界」＋ADR 0040 後果之「七支檔逐支以路徑寫出、任一塊皆不得以『三檔』『四檔』等無路徑概稱
  替代」；★該句的實際射程須誠實界定——它是對**承載檔集的那一列（(i)）**所立的規則（其所防
  的是以計數概稱掩蓋實際檔集），而 (iv) 形是**指名交叉引用到一個已逐支寫出的列**、檔集仍
  完全確定，非該句所禁之無路徑概稱。取逐支寫出的代價＝上列①之兩處新增字面相牴＋③之兩份無
  機器守的重複清單，收益＝表內單列可讀性。兩形之授權射程相同（產物四檔皆受 (i) 列產物檔
  紀律與重算冪等閘涵蓋），故改取任一形皆不影響授權語意。
- **紀律欄以「沿用途 (i) 之紀律欄全文」引用而不整段照抄**：(i) 的紀律欄已寫成本軌道共同
  紀律的權威敘述（含機器守實況誠實揭露段），(iv) 即以「形照 (i)」引用之——照抄一次就多
  一份會漂移的鏡像。本案沿 (iv) 慣例、只寫本用途專屬差異。
- **view 新檔不入名冊的理由**（表外宣告 3＋ADR 0021 款 1＋§III.1）：★軌道授權射程＝
  **inline（改動 base-web 既有檔）**；view 新檔為最原始源基線不存在之純新增檔，依 ADR 0021
  款 1 不觸★軌道、依 §III fork-delta 新增型紀律以檔頭一行 `rev5-inline` 標記落地即可。
  §III.1 三軌道表＝常用新增面之預設清單、**非新增面之窮舉排除**——view 新檔雖不在三軌道
  之列仍屬純新增面。機器面：表外宣告 3 載明名冊斷言的射程僅修改型（帶 `原行:`）、新增型
  標記不入名冊——把 view 新檔寫進範圍欄不會多任何機器守，反而把「名單＝修改型硬邊界」的
  語意稀釋掉；故兩列僅以說明句記其存在與不入名冊之依據（同 (iv)(v) 先例）。

### 款二：稽核域行為島——入憲（島 J；T003 親決題① user 親決取甲案，乙案整段移入「考慮過的替代案與棄用理由」節）

**共同事實底座**（兩案共用、不因選案而變）：本刀落地的 purge 域行為（spec FR-C01～C04）＝
①來源表限四值白名單（operationLog／accessLog／loginAttempt／sessionEvent）②保留天數下限
`PURGE_MIN_DAYS`＝30 ③單交易水平線 DELETE＋同交易操作日誌自記 ④操作日誌版 DELETE 豁免歷史

（自記失敗即整筆回滾、fault-injection 釘住、B-125）；另有讀面行為（FR-A02／FR-B02）＝四源
唯讀、授權面 seed 預設僅超管（五支端點 seed `protected`＝FALSE ⇒ 超管 MAY 於運行期下放、
非憲法禁令——見子選項 A）、逐欄構造 DTO、PII 讀出端打碼。

**★詞彙前置條件（兩案共用、不因選案而變）**：上述④之豁免述詞在 rev5 的字面**必為小寫**
`operation <> 'purge'`，且該字面**目前不存在**——三筆機器事實：

1. `rust-api/server/src/model/audit.rs` 的 `audit_operation_vocabulary!` 單一宣告源展開之
   `AuditOperation` 現為**恰八值、全小寫**（add／update／delete／restore／unlock／kick／
   reset_password／change_password）；`AuditEvent.operation` 的欄型即該 enum ⇒ purge 自記列
   在型別上根本寫不出來，除非先加第九值。
2. 同檔測 `t013_user_password_family_adds_three_vocabulary_stays_eight` 斷言
   `AuditOperation::ALL.len() == 8`、訊息逐字「定案：詞彙集恰八值……變動＝推翻定案、須新 ADR
   連同本測改寫」；同測另有大寫腿以判準 `WHY_UPPERCASE`（逐字「rev4 大寫 DB 動詞形不得帶回」）
   攔下 `ADD`／`SOFT_DELETE` 之類字面。
3. 故 rev4 島 J3 原文的 `PURGE` 大寫形（rev4 憲法 §I.7 島 J3；rev4:server/src/handler/audit.rs
   與 rev4:server/src/bin/reaper.rs 皆用 `operation='PURGE'`／`operation <> 'PURGE'`）正是
   ADR 0019 明令不得帶回的 rev4 字面。本刀 SDD 包現仍多處沿用該大寫形＝rev4 殘留，其改對
   不在本單元（U0）允許檔面內、須由主線處置。★**待改對面以掃源現算、不落字面名冊**（落字面
   即第二份會腐化的名冊，L-038／CLAUDE.md §4 勘誤條）：`grep -rn "PURGE" specs/008-audit-settings-pages/`
   逐處判別後改對——命中分兩類，**屬詞彙值者**（`'PURGE'` 述詞與「PURGE 自記」散文）全數
   改小寫、**屬常數名者**（`PURGE_MIN_DAYS`）大寫正確、不在射程；改完以同一指令復掃驗收。
   ★本檔起草時（2026-09-01）該指令之詞彙值類命中為**四行三檔**：`tasks.md` 之 T014 與
   User Story 3 檢查點行、`data-model.md` §3、`quickstart.md` 走查清理面——此為現況快照、
   非權威名冊，主線一律以現算結果為準。

- **§I.6 變體 B 括號句維持現形、零改動**：該句自備過渡語意「在此之前以本句為準」，故
  **不懸空**——句子本身就是現行權威、不因乙案成假述。待決狀態的實質＝「權威釋義的兌現點
  順延」：本 ADR 補記本刀 purge 之水平線刪除即該句所指 retention 的首個 as-built 實例、
  該句承諾的兌現點順延至日後島 J 進場刀（候選＝B-016 寫入面刀）；不改句、不加字，防止
  「改一句過渡語意」演成無 bump 的實質修憲。
- **乙案代價**：稽核域成為「有已驗證不變式、無憲法凍結」的域。★**此處誠實計價、不得寫成
  「§IV 第 9 題零觸發」**：該題逐字為「此 plan 是否觸及 §I.7 已入憲的行為島？……**若屬「該
  入憲而未入憲」的新行為島、是否隨本刀排入 Amendment（候選來源＝啟動書 §5 K1 承襲清單）？**」
  ——末腿明文以**未入憲域**為標的，而稽核域正在該 K1 清單內 ⇒ 乙案下後續刀的 plan
  Constitution Check **仍會觸發該題**，只是觸發的內容不同：由「各 invariant 是否保持」的
  **逐條對照**降為「要不要隨本刀入憲」**一問**。真正的代價即這一級落差——防線由「每刀被強制
  逐條核對方向」降為「每刀被問一次要不要入憲」，凍結力降一級為 ADR accepted，日後刀若不查
  DECISIONS-INDEX 便可能無感地改壞方向（僅測試層兜底）。§I.6 句繼續指向一個未到來的時點。
- **乙案後果**：島 J 留待 B-016 一次成形（J1～J5 齊、無空缺位）、避免殘缺島；本刀 U0 落字
