## 背景

創世 B11：前代知識匯出包無默認繼承、須逐筆有去向。rev4 先例是在其 bootstrap B8 當場由
user 逐筆拍板；rev5 於 B5 拍板閘 Q5 選甲案「不預載」——承襲細目不進憲法 v1.0.0，改以
§I.7／§III.2 指針句各一句＋§IV Compliance Check Q9 補註（候選來源＝啟動書 §5 K1）導向，
故 K1 的處置點分散到各刀階段 0。B11 因此只記**機制**與 **K2 分流**，不在本步逐筆拍方向。

啟動書屬創世史料、此後不再更動；本 ADR＋BACKLOG＋各刀 ADR 為這批知識的唯一承接載體。

## 決定

### 一、K1（88 筆）＝機制型處置

1. **constitution 級**：已於 B5 隨憲法 v1.0.0 由 user 逐條親審定版（Q5 甲案＋指針句×2＋Q9 補註）。
2. **八疲態域**（啟動書 §2.4）：各自的刀動工前逐域走階段 0 重審、不預先拍方向——
   ①base-web fork-delta 軌道治理 ②schema 凍結基線與 schema-gate ③登入節流與 fail 方向
   ④會話生命週期與 auth 觸面 ⑤i18n／msg key 契約 ⑥ingress 信任錨與部署前提
   ⑦機密選型與落點 ⑧稽核資料生命週期。
3. **其餘沿用項**：隨其刀立 ADR，front-matter 記 `provenance: "rev4:…"` 純字串族譜（非依賴）。
4. **首例已發生**：001 schema 基線刀消費 K1-13／14／15／21／23／24／32／39，落
   ADR 0006（provenance `rev4:0014`＋`rev4:0021`）與 ADR 0007（承 K1-32／39 重審結論）——
   第②疲態域由此結案，示範本機制可運轉。
