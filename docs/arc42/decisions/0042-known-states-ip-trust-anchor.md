## 背景

沿 003-auth-session 之 ADR 0033 立下的形制：一把刀交付後，**刻意不做**與**做了但有邊界**的
事實須有一個活的家，否則只會留在該刀的 spec 裡而 spec 收刀後即成史料。本檔承載 004 的
已知態集，並兌現 ADR 0039 逐字指定的解除謂詞。

## 決定

### 續存已知態（四項）

1. **快取持久化模式維持不開**（重評結論）。此重評觸發器由前一刀明文掛在 B-019 條目上
   （003 spec 逐字「prod 化由 B-019／部署刀重評」）。**結論＝維持現狀不開**，論證＝本刀新增
   的 IP 維暴險受「**權威源即真相**」封頂：①存取閘判定面在記憶體、規則的真相在資料庫，
   快取只承載門鈴（PUBLISH），快取整批遺失至多使跨副本重載延遲到下次重讀，判定不失真
   ②來源維節流的權威是資料庫滑動窗、快取為負快取層 ③解鎖標記遺失的後果是「該標的可能仍
   被鎖」，操作者**再解鎖一次即自癒**。⇒ 無不可回復的損失面，開啟持久化的成本大於收益。
2. **解鎖端點無 UI 按鈕**。本刀交付 `POST /systemManage/unlockLogin` 與其 casbin 政策列
   （seed 已在），但**不建**前端包裝與按鈕——理由是解鎖的操作入口自然歸屬「稽核／登入紀錄
   管理頁」，該頁不在本刀射程。★可見落差：超管在 UI 上找不到解鎖入口，須由呼叫端（腳本／
   走查）直打端點。
3. **dev 經反向代理可達的信心態恰兩態**＝`fallback`（預設瀏覽行為）與 `proxy_clean`
   （帶構造轉發標頭）。其餘五態（`direct`／`proxy_soft`／`cdn_anchored`／`cdn_verified`／
   `cdn_mismatch`）在 dev 拓樸下**結構性不可達**，逐態理由見 research R7；七態逐態覆蓋落在
   整合測試層（直餵信任模型＋任意對端與標頭），與端到端走查**射程不同**。
   ★本項**校正** spec FR-044 的殘句「開發環境全直連」——該措辭寫於 Clarify Q1（dev 掛最小
   信任模型）拍板之前；掛了設定之後容器網段已入受信集，`direct` 反而是**不可達**態。
4. **稽核覆蓋不對稱**。本刀是 rev5 `sys_operation_log` 的首個寫入者，但只為**本刀新端點**
   落列（IP 規則四寫端＋解鎖）；**既有 system settings 寫端維持不落列、不回改**
   （002 之 FR-016 刻意決定）。⇒ 操作稽核表的覆蓋面目前是「有 IP 規則與解鎖、無設定變更」，
   查詢端不得據此表宣稱「所有管理操作皆有稽核」。

### 重評不動（一項；★tasks T003② 未列、本檔補入以免其只存在於測試檔註解）

5. **線上契約裁判面未開「禁止額外欄位」嚴格模式**＝已知態，本刀重評結論為**維持不動**
   ——動快照生成器會牽動既有全部路由的裁判行為、屬 wire 地基面。本刀僅更新該面的警示句
   （落點＝`rust-api/server/tests/wire_schema.rs` 之「裁判面界線」註記；只改註解、零斷言
   改動、零快照改動）。

### 解除既有已知態（一項）

6. **明文解除 ADR 0039**（`ip_captcha_after`／`ip_max_fails`／`ip_window_minutes` 三鍵已 seed
   但零執行面消費者）。0039 逐字指定其解除謂詞＝「B-019 落地」，本刀即是：三鍵的讀取端由
   `throttle::load_ip_settings` 落地（tasks T047），改值**真的改變**來源維軟／硬門檻與窗長，
   且該真消費以「把三鍵改成與 seed 不同的值、斷言門檻隨之改變」的機器測自證（tasks T045）。
   轉 accepted 時 `supersedes: ["0039"]`。
   ★**誠實界線**：解除的是「零消費者」這一件事，**不是**「三鍵已全面驗證」——`ip_max_fails`
   之硬鎖在 dev 拓樸下仍受「不帶構造轉發標頭即全站共用單一來源桶」影響（本檔第 3 項），
   走查時須帶標頭才驗得出計數隔離。

## 後果

- 本檔為 004 已知態的**唯一活家**；四項續存項各自的解除謂詞：①快取暴險面出現不可回復損失
  （或 prod 化決策翻案）②稽核／登入紀錄管理頁刀 ③dev 拓樸取得 CDN 前置 ④設定寫端補落稽核列
  的刀。⑤之解除謂詞＝wire 地基刀。
- 第 6 項落地後，`system_settings` 的 `ip_*` 三鍵自此可被當作「已生效的安全設定」向操作者
  陳述——這正是 0039 後果段所禁止的事，其禁令隨本檔解除。★但**帳面不實的風險反向存在**：
  若本刀最終未交付 T047 之讀取端，本檔第 6 項即為假；故 T047 的 DoD 逐字要求「三鍵真消費
  自證」一案，該案綠即本項為真。
- 本檔**不動搖**既有已知態集所依賴的兩條承重論證（spec FR-045）：撤銷名單機制與「狀態即
  權威」零鬆動；13 碼矩陣與其例外集零觸碰（本刀阻擋復用 `5003`、規則錯誤與解鎖畸形復用
  `2222`，零新錯誤變體）。
