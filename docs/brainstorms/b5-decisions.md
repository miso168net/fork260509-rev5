## Q5・憲法 §I.7 行為島／§III.2 軌道細目是否預載 v1.0.0

**裁決：甲案——不預載。v1.0.0 僅搬進場規則與機制骨架，約 165–175 行。**

- **搬什麼**：§I.7 只搬約 5 行進場規則（本節為凍結位、隨刀填充、島以 MINOR Amendment 入本節、方向性反轉為 MAJOR、常數與欄級細節留活書）；§III.2 只搬約 8 行機制骨架（軌道概念、「嚴格限已授權用途、新用途走 §V.2 Amendment」、補完 vs 新能力四條件判準、零新 key 釋義、spec 內紀錄義務、共用元件附加 prop 慣例）。
- **不搬什麼**：十座行為島 A～J 細目約 52 行、五個具名 ★ 軌道與 (a)～(k) 十一用途細目約 64 行——每條都掛 rev4 刀號（006～017）與 ADR 號，§III.2 每款指名 rev4 具體檔案路徑；且憲法自身條文明訂「隨其刀拍板後才入憲」「新用途走 Amendment」，**預載即自我違反**。
- **內容不丟失**：細目已收在 K1 承襲清單（K1-44 IP 閘、K1-48 授權治理、K1-52 選單島等），對應刀的階段 0 直接取材、隨刀 MINOR Amendment 重新入憲。此即 rev4 自身先例（K1-01：17 題重鑄、行為島留空位，程序零翻案）。
- **連動面（B5 施工必做）**：
  1. §I.2 末句刪指向 §III.2 第 (k) 款的括號句「（如 (k) 強制改密頁）」——不刪即懸空引用（§4.5.6 條 3 已明載）。
  2. §I.6 變體 B「retention 水平線刪除不屬竄改」對島 J3 的交叉引用改寫為自足敘述（§4.5.6 條 7 已明載）。
  3. 定版底稿依 §4.5.6 末尾的 v1.0.0 範本（該範本即甲案形，L963）。
- **代價（已認知）**：第一把撞到對應域的刀要多走一次 Amendment（例：第一刀撞 base-web inline 時才開 §III.2 第一款）。

## Q11・薄手冊「絕對禁令」段是否新增「掃描防線就位前不落任何 commit」

**裁決：甲案——新增。D 段七條→八條。**

- **條文形（B5 落檔草案，定稿以親審為準）**：「絕不在掃描防線就位前落任何 commit（含子庫與新機器；bootstrap 驗證通過＝就位）」。
- **為何這樣拍**：機密一旦入史就永久留在 git 物件庫；而機器閘（pre-commit 掃描）在 hooks 未接上的窗口期**不存在**——B9 子庫建置、新機器 clone 後 bootstrap 前，唯一防線是教義層。rev4 實證失效：本機兩子庫 worktree 的 `core.hooksPath` 皆查無＝掃描防線從未就位（啟動書 L618）。
- **連動面**：
  1. B5 落薄手冊時即寫入（本條是 rev5 對 rev4 七條之外的唯一新增，其餘七條原樣照搬——§4.7 D 段盤點結論）。
  2. 與 B9 施工序互為印證：hook 保護先於子庫首 commit（task #22 既有排序）。
  3. B6/B9 驗收條件「設完讀值回驗 core.hooksPath」承接機器面（啟動書 L618 既有要求）。

## Q12・「輕量軌」是否寫進薄手冊第 2 節

**裁決：甲案——寫進第 2 節，補一小段（約 3–5 行）＝判準＋程序。**

- **內容形（B5 落檔草案）**：判準＝維護項／小修不開 SDD；程序＝分支 → 編排單元 → merge → misc 事件收單（backlog_done 通道消化 BACKLOG 條目）。內容依據＝啟動書 §4.7 F 層表格「輕量軌」列（L1613）。
- **為何這樣拍**：
  1. 軌道選擇是每個工作項起手的第一個分岔，現行第 2 節骨架只寫 SDD 單軌——照字面會把維護項拖進過重的全流程。
  2. rev4 靠隱性慣例跑好（44 次收刀 24 次走輕量軌、補遺率 1/44≈2.3%），但慣例不保證跨世代傳承；rev5 換環境重開，需要明文。
  3. 非新發明：backlog_done 欄位已是 user 拍板調規（2026-07-17）、Lint04/Lint05 對賬已存在——條文只是把 as-built 實況寫成規則。此缺口啟動書 §4.7 已標 ★ 提醒（L1627–1629：rev4 終態有、骨架未列、需另行拍板）。
- **連動面**：第 2 節約 57→60 行，仍在薄手冊 ≤250 行預算內（Lint07 強制）；B5 落檔時寫入。
