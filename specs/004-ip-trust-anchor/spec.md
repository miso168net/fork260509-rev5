  建議**（FR-005、FR-043）。

### Session 2026-08-12（`/speckit-clarify`）

- Q: 開發環境要不要附一份最小的信任模型設定，把反向代理容器的網段列為「可信轉發層」？→ A:
  **要**——交付一份開發環境信任模型設定（僅把容器網段列入內網預設集、其餘集合留空）並隨
  compose 掛載（FR-010 後段）。★理由是**拓樸正確性**而非驗收便利：後端的傳輸層對端恆為反向
  代理，它若不在信任集，對端閘（第一層）恆先觸發 ⇒ 第二／三層與兩個覆蓋層在**任何環境**
  （含 prod）都是死碼、整套 IP 域形同虛設。連帶解除三項端到端不可驗（阻擋生效／來源維計數
  隔離／防自鎖），並使部署 checklist 的設定樣例成為**跑得起來的活體**而非沒人驗過的文件。
  ★查證所得（rev4 藍本缺陷、**不帶回**）：rev4 驗收手冊第 3 節寫了「構造轉發標頭模擬公網來源」
  四步走查，但其 compose／`.env`／部署腳本**從未設過**信任模型設定 ⇒ 全空集合下對端閘恆先
  觸發、構造標頭一律被忽略，該四步跑不出宣稱結果（其手冊自稱「信心恆為回退態」亦與全空設定
  應得的「直連態」不符）。
- Q: 轉發鏈中無法解析成位址的欄位（`unknown`、截斷字串、夾帶連接埠或 IPv6 區域識別的寫法）
  該怎麼處理？→ A: **丟棄該欄位**（沿前代已驗證語意）——右端取窗後逐欄正規化（剝連接埠／
  區域識別／方括號），仍不可解析者丟棄、永不當機；丟棄語意＝「該跳不存在」、鏈的相對次序
  不變（FR-009）。★此為**安全性要求非實作偏好**：另兩種候選各自開出可利用破口——「遇不可
  解析即中止整條鏈」使攻擊者插入單一垃圾字串即可讓任意拓樸退化並操縱錨的左鄰；「保留為
  佔位跳」使該佔位跳參與硬化檢查與最右非受信判定，等於讓垃圾字串直接操縱判定結果。
  三種語意 MUST 有區辨性測試。
- Q: 新頁面會讓路由外掛重新產生的三支路由生成檔，在 fork 差異標記紀律下該怎麼歸屬？→ A:
  **以「產物檔」身分治理**——軌道條文寫「僅由外掛重算產出、禁止手改」，驗收＝**重算冪等
  檢查**（重跑外掛後與版控內容零差異），並於條文內明寫「不要求逐行原文標記」及其理由：
  標記於下一次重算即被抹除、物理上不可維持，寫進紀律等於立一條保證會被違反的規則（FR-041）。
  ★冪等檢查的強度**高於**逐行標記——標記僅是註解、無強制力，冪等檢查連單行手改都抓得到。
  棄案＝「逐行標記＋每次重算後人工補回」（必然漂移）與「三檔改為不納入版控」（動 upstream
  既定架構、與「不留 upstream 衝突風險高的改動」相抵）。
  ★**檔數校正**（拍板語意不變、僅更正事實）：提問與棄案敘述當時寫「三支／三檔」，實查外掛
  產物為**四支**——`src/router/elegant/{imports,routes,transform}.ts` ＋
  `src/typings/elegant-router.d.ts`（四支檔頭皆帶 `Generated by elegant-router`；rev4 同頁
  落地之 codegen commit 亦恰動這四支）。FR-041／SC-011 以四支為準。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 稽核紀錄記下真實來源與其可信度 (Priority: P1)

稽核者翻閱登入紀錄時，看到的來源位址是**真實使用者的位址**、而非最近一跳代理的位址；且每一列
都標明該位址是怎麼判定出來的（直連觀察／CDN 背書／轉發鏈推導／退化回退），使「這筆紀錄能不能
當證據」變成可讀的事實而非猜測。攻擊者即使偽造轉發標頭，也無法讓系統把別人的位址記成自己的
來源、或把自己的位址藏起來。

**Why this priority**: 這是整個 IP 域的地基——存取閘擋誰、節流鎖誰、稽核記誰，全部取決於這一步
還原出的位址。它單獨交付即有價值（稽核真實性立即提升），且下游三個故事都以它為前提。

**Independent Test**: 直接對後端服務注入各種「傳輸層對端×轉發鏈×信任設定」組合，斷言還原出的
位址與信心等級逐案正確；並實際登入後查稽核列的來源三欄（對端位址／真實位址／信心等級）如實落庫。

**Acceptance Scenarios**:

1. **Given** 信任模型未宣告任何可信轉發層（設定缺席或全空）, **When** 使用者登入, **Then**
   真實來源＝傳輸層對端位址、信心＝直連，轉發標頭一概不採信。
2. **Given** 信任模型已宣告某 CDN 網段且請求經該 CDN 進來, **When** 使用者登入, **Then** 真實
   來源＝CDN 標示的訪客位址、信心＝CDN 位置錨（若另帶邊緣驗證標記則升為 CDN 已驗證）。
3. **Given** 攻擊者繞過 CDN 直連來源站, 並在轉發鏈裡偽造一段公開可查的 CDN 邊緣位址當錨,
   **When** 該請求進來, **Then** 錨**不成立**（錨右側存在不受信任的一跳＝反向代理實際觀察到並
   附加的攻擊者位址）、判定退下一層而解出**攻擊者自己的位址**——偽造的來源位址完全落空，
   存取閘與節流照常對其生效。
4. **Given** 轉發鏈裡帶有 IPv4-mapped IPv6 形位址, **When** 還原完成, **Then** 全下游（存取判定
   ／節流計數／稽核落列）拿到的是同一個正規化形，不會分裂成兩個身分。
5. **Given** 信任模型設定檔存在但內容損壞, **When** 服務啟動, **Then** 服務照常啟動並發出降級
   告警、信任集合退為全空（等同全直連）——**不擴大**信任範圍、不當機。
6. **Given** 開發環境已掛載最小信任模型（反向代理容器網段列為可信轉發層）, **When** 走查者經
   反向代理發出帶構造轉發標頭的請求, **Then** 系統依轉發鏈推導真實來源（而非取反向代理自身
   位址）——使開發環境得以模擬任意公網來源，阻擋、來源維計數隔離與防自鎖三者自此端到端可驗。

### User Story 2 - 超管以 IP 規則阻擋或放行特定來源 (Priority: P2)

超級管理員可以宣告「這些來源一律擋下」與「這些來源一律放行」，規則一存檔就立刻生效、不需要重
啟服務。放行永遠贏過阻擋；本機與內網等基礎設施網段永遠不會被規則擋在門外（避免管理者把自己與
維運通道一起鎖死）。規則資料庫暫時讀不到時，判定面沿用上一份已知良好的規則，而不是清空成無防護。

**Why this priority**: 這是 IP 域對外可見的第一個防護能力；但它必須建立在 US1 還原出的正確位址
之上（擋錯位址比不擋更糟），故排在 P1 之後。

**Independent Test**: 建立阻擋規則後以該來源請求，斷言被拒；建立同來源的放行規則後再試，斷言
放行；對本機位址建阻擋規則，斷言仍然放行；模擬規則來源暫時不可讀，斷言沿用前一份規則。

**Acceptance Scenarios**:

1. **Given** 對某網段建立阻擋規則, **When** 該網段的請求進來, **Then** 請求被拒（權限不足類回應
   ＋對應的 HTTP 狀態），並留下一筆可查的阻擋紀錄。
2. **Given** 同一網段同時存在放行與阻擋規則, **When** 該網段請求進來, **Then** **放行**（放行
   優先於阻擋，且與規則建立先後無關——規則是集合、沒有優先序欄位）。
3. **Given** 對本機／內網網段建立阻擋規則, **When** 該來源請求進來, **Then** 仍然放行（結構性
   豁免；★該豁免只豁免「阻擋」，**不**豁免來源維節流）。
4. **Given** 服務正在運行且已有規則生效, **When** 超管新增／修改／刪除／復原任一規則, **Then**
   判定面在無需重啟的情況下更新，後續請求即依新規則判定。
5. **Given** 兩袋規則皆未命中, **When** 請求進來, **Then** 放行（預設放行）。
6. **Given** 健康檢查與觀測端點, **When** 任何來源請求, **Then** 一律不受 IP 規則影響（永遠可達
   ——否則故障期間連健康狀態都看不到）。

### User Story 3 - 超管在管理頁維護 IP 規則 (Priority: P2)

超級管理員從側邊欄進入「IP 規則管理」頁，看得到現有規則清單（含類型、網段、備註與建檔／異動
軌跡），可依網段模糊搜尋、依類型與是否已刪篩選，並以抽屜表單新增與編輯；刪除為可復原的軟刪、
回收桶內可一鍵復原。**若一條規則會把操作者自己鎖在門外，系統當場拒絕寫入並說明原因**。

**Why this priority**: 沒有這一層，US2 的五支端點是零消費者的斷頭交付，且「防自鎖」這個唯一的
fail-closed 例外無法在真實操作流程中驗證。與 US2 同級。

**Independent Test**: 以超管身分在瀏覽器完成「列表→搜尋→新增→編輯→軟刪→回收桶復原」全程，
並與前代同頁做視覺與行為對照；另以「建立一條涵蓋自己來源的阻擋規則」驗證當場被拒。

**Acceptance Scenarios**:

1. **Given** 超管已登入, **When** 開啟側邊欄的「IP 規則管理」, **Then** 頁面正常載入（此前該
   選單列存在但點擊得「找不到資源」＝已知態自此解除）並顯示規則清單與四顆操作按鈕。
2. **Given** 清單有多筆規則, **When** 以網段片段搜尋、以類型或刪除狀態篩選, **Then** 結果正確
   且分頁資訊一致。
3. **Given** 新增表單填入帶主機位元的網段（例如 `203.0.113.7/24`）, **When** 送出, **Then** 落庫
   為正規化網段（`203.0.113.0/24`）——避免同一網段以不同寫法繞過唯一性。
4. **Given** 已存在某網段＋類型的有效規則, **When** 再建一筆完全相同者, **Then** 以業務錯誤拒絕
   （非伺服器錯誤）並提示衝突。
5. **Given** 操作者當前來源位址落在某網段, **When** 嘗試建立涵蓋該網段的阻擋規則, **Then**
   **拒絕寫入**並說明「此規則會使你自己無法連線」。
6. **Given** 一筆已軟刪的規則, **When** 於回收桶按復原, **Then** 規則回到有效狀態並即時生效。
7. **Given** 規則備註欄填入含 HTML 標記的文字, **When** 清單渲染該欄, **Then** 顯示為純文字原文
   （不被當成標記執行）。

### User Story 4 - 來源維登入節流真正生效 (Priority: P3)

同一個來源在短時間內大量嘗試登入（即使每次換不同帳號名）時，系統會先要求圖形驗證碼、再進一步
鎖定該來源至時間窗滑過為止；此判定與既有的「同一帳號連續失敗」判定**並行**，任一方觸發即生效。
系統設定頁中三個來源節流參數自此**真的會改變行為**（在此之前它們可修改、有值、但無任何效果）。

**Why this priority**: 補上「輪換帳號名」這個既有帳號維節流擋不住的攻擊面；但它依賴 US1 的位址
還原（沒有可信來源位址，鎖定會誤傷共用出口的整批使用者），故排 P3。

**Independent Test**: 以同一來源輪換帳號名連續失敗登入，斷言在軟門檻要求驗證碼、在硬門檻鎖定；
並斷言穿插一次成功登入**不會**重置來源計數。

**Acceptance Scenarios**:

1. **Given** 某來源在時間窗內失敗次數達軟門檻, **When** 再次嘗試登入, **Then** 要求圖形驗證碼
   （即使該次使用的帳號名從未失敗過）。
2. **Given** 某來源在時間窗內失敗次數達硬門檻, **When** 再次嘗試登入, **Then** 拒絕並提示鎖定；
   拒絕發生在密碼雜湊驗證**之前**，且**不留稽核列、不消耗計數**（拒絕不得替攻擊者延長鎖定，
   也不得消耗受害者的額度）。
3. **Given** 某來源已累積失敗次數, **When** 攻擊者以一組有效帳密穿插一次成功登入, **Then** 該
   來源的失敗計數**不重置**（★此為刻意與帳號維不同的方向：帳號維成功即重置是正確的，移植到
   來源維會成為破口）。
4. **Given** 帳號維與來源維同時判定, **When** 任一維觸發鎖定, **Then** 結果為鎖定；皆未鎖定但
   任一維進入軟區, **Then** 結果為要求驗證碼；否則放行。
5. **Given** 某來源命中**顯式放行規則**, **When** 該來源嘗試登入, **Then** 跳過來源維節流；
   **Given** 某來源只是落在結構性豁免網段, **Then** **不**跳過來源維節流。
6. **Given** 同一使用者以 IPv6 位址請求, **When** 計數, **Then** 以聚合前綴計桶（避免攻擊者
   在單一分配內換位址規避）。

### User Story 5 - 超管手動解鎖被鎖的帳號或來源 (Priority: P3)

當某個帳號或某個來源被節流鎖定，超級管理員可以立即解除，不必等待時間窗自然滑過；解除動作本身
留下稽核紀錄，且**稽核先於生效**（不存在「已解鎖但查不到是誰解的」這種狀態）。

**Why this priority**: 補上既有帳號維節流「有鎖無解」的缺口（該解鎖標記的讀取端早已備妥、
但從來沒有寫入者），並讓 US4 的來源維鎖定在誤傷時有自癒手段。

**Independent Test**: 先把某帳號與某來源各鎖到硬門檻，呼叫解鎖後斷言立即可再次嘗試登入，
並斷言解鎖動作留下操作稽核列。

**Acceptance Scenarios**:

1. **Given** 某帳號已被鎖定, **When** 超管對該帳號解鎖, **Then** 該帳號立即可再次嘗試登入。
2. **Given** 某來源已被鎖定, **When** 超管對該來源解鎖, **Then** 該來源立即可再次嘗試登入。
3. **Given** 解鎖請求的參數畸形（維度不明或標的無法解析）, **When** 送出, **Then** 以業務錯誤
   拒絕，且**不留稽核列、不動任何狀態**。
4. **Given** 稽核紀錄寫入失敗, **When** 執行解鎖, **Then** **中止**、不解鎖（「生效但零稽核列」
   在構造上不可達）。

### Edge Cases

**信任錨**

- 轉發鏈長度超過上限（極長鏈或洪泛）→ 只保留**最右側**固定數量的段、丟棄左端溢出（真實來源在
  鏈的右端；方向寫反即開出「以左端洪泛把真實位址擠出視窗」的攻擊面）。
- 轉發鏈含無法解析為位址的段 → **丟棄該段**（＝該跳不存在），鏈的相對次序不變、整條鏈的判定
  不塌陷（FR-009）；帶連接埠、IPv6 區域識別或方括號包裹的合法寫法先正規化再解析、不算畸形。
- CDN 位置錨成立但錨左側找不到非 CDN 段 → 錨不適用、退下一層。
- 帶邊緣驗證標記但傳輸層對端不在「掛驗證閘的我方出口集」內 → **不得**升等（防直連形態下自帶
  偽造標記騙升最高信心）。
- 邊緣驗證標記為真但訪客位址標頭缺值 → 不升等；標記與推導結果不一致 → 降為「不一致」信心，
  **只動信心、不動位址**。
- 信任模型設定檔缺席 → 沿用扁平環境變數退路；設定檔存在但整體損壞 → 全空（★**不**套用退路
  ——設定存在但壞掉時擴大信任是錯誤方向）；單一集合含無效網段 → 只清空該集合（只縮小信任）。
- 前一代「來源位址缺席→空字串→由資料庫型別擋下」的路徑**消失**：傳輸層對端恆有值 ⇒ 直打後端
  的整合測試自此落在「直連」態，既有的顯式注入輔具需重整（消費面可見的行為反轉，FR-011）。

**存取閘**

- 規則來源在服務啟動時讀不到 → 空集合放行（不因設定讀不到而把所有人擋在門外）。
- 服務運行中規則來源暫時讀不到 → **沿用上一份已知良好規則**、不清空。
- 熱重載通知管道故障 → 放行方向降級並告警；不得因通知管道故障而讓判定面停止服務。
- 規則表被以非正常途徑塞入未知類型的列 → 該列略過、不使整份規則集失效。

**規則管理**

- 同網段＋同類型且皆有效 → 唯一性衝突，以業務錯誤拒絕。
- 同網段＋同類型但舊列已軟刪 → 可建立新列（唯一性只約束有效列）。
- 網段字面帶主機位元 → 落庫前正規化（否則同一網段的不同寫法可繞過唯一性）。
- 對不存在或已刪除的規則執行更新／刪除／復原 → 以業務錯誤回覆，不製造伺服器錯誤。
- 防自鎖檢查在「操作者來源恰好落在結構性豁免網段」時的行為需明確（豁免段本就擋不住，故不應
  誤判為自鎖）。

**節流與解鎖**

- 快取層整體不可用 → 沿用既有帳號維方向（軟區驗證碼要求整層停用、續驗密碼；密碼錯仍計數）。
- 解鎖標記讀取故障 → 視為**無標記**（該來源可能仍在鎖定中），不得因讀不到而放行。
- 走查期間累積失敗導致自我鎖定 → 以解鎖端點自癒。★開發環境掛載最小信任模型後，走查若**不**
  帶構造轉發標頭，所有流量的真實來源仍收斂為同一位址、共用單一來源桶（此形容易誤觸鎖定），
  故驗收程序 MUST 明示「模擬公網來源時帶構造標頭、且該位址需落在結構豁免段之外」。

**管理頁**

- 備註欄含標記字元 → 純文字呈現。
- 使用者無對應按鈕權限碼 → 該操作按鈕不呈現（沿既有權限碼機制）。

## Requirements *(mandatory)*

### Functional Requirements

**端點與路由**

- **FR-001**: 路由註冊表 MUST 由 16 條擴為 22 條，新增六條且路徑與動詞逐字對齊 001 凍結 seed
  之政策列：`/systemManage/getIpRuleList`（GET）、`/systemManage/addIpRule`（POST）、
  `/systemManage/updateIpRule`（POST）、`/systemManage/deleteIpRule`（DELETE）、
  `/systemManage/restoreIpRule`（POST）、`/systemManage/unlockLogin`（POST）——六條**全為
  政策保護**（`Protection::Policy`）。
- **FR-002**: 本刀 MUST 為**零 migration、零 seed 變更**：六條政策列（seed 143–148）、四顆
  `ipRule:*` 按鈕碼（160–163）、`user:unlock` 按鈕碼（157）、`manage_ip-rule` 選單列與其 menu
  維政策列（149）皆已在 001 凍結 seed；三張稽核表的 `ip_confidence` 為無 CHECK 約束之 text，
  由單一字面擴為七態字面集**不需 DDL**。★spec 明寫此點，防 review 質疑「政策設得進、端點不
  存在」與「換字面要不要加 CHECK」。

**信任錨——真實來源還原（US1）**

- **FR-003**: 真實來源位址與信心等級的**政策判定 MUST 只存在於單一純函式**；請求層只負責抽取
  標頭與傳輸層對端、呼叫該函式、把結果組成請求上下文，**零內聯重複判定**。下游（存取閘判定、
  來源維計數、稽核落列、防自鎖檢查）一律消費同一結果，不得各自重推。
- **FR-004**: 還原 MUST 依固定三層序：①**對端閘**——傳輸層對端不屬信任集合即直取對端位址、
  完全忽略轉發鏈，信心＝`direct`；②**Tier-1 CDN 位置錨**——以轉發鏈中**最右側**的 CDN 段為錨、
  取其左鄰第一個非 CDN 段為真實來源、剝除錨右側全部，信心＝`cdn_anchored`；錨左無非 CDN 段即
  退下層；③**Tier-2 最右非受信**——由右往左跳過跳過集，第一個不屬跳過集者即真實來源。
- **FR-005**: ★**Tier-1 錨 MUST 附傳輸層背書條件**（本刀新拍板、兌現 rev4 未做之硬化案）：
  錨成立**額外要求**「錨右鄰起、直到傳輸層對端為止的每一段，皆屬受信基建集合」；任一段不屬即
  **錨不成立、退 Tier-2**。受信集合 MUST 與 Tier-2 跳過集由**同一 helper 導出**（不得為硬化
  另立第三個集合——兩集合分叉即是前代缺陷的復發形）。
  ★此條使「部署方必須鎖定來源站僅接受 CDN 邊緣連線」自**承重安全前提**降級為**縱深防禦建議**
  （FR-043）；合法 CDN 路徑下錨右側為空集合、硬化條件恆成立 ⇒ **對合法流量零行為改變**。
- **FR-006**: 兩層覆蓋（overlay）MUST 依前代已驗證形：①**通道回退**——基礎判定為回退且對端屬
  通道來源集時採信通道注入的訪客位址標頭，**信心維持回退、不升等**；②**邊緣驗證升等**——
  四個前置**全中**才升等（對端屬「掛驗證閘的我方出口集」／驗證標記為真／訪客位址標頭有值／
  基礎信心屬可升等集合），升為 `cdn_verified`；驗證標記為真但推導結果不一致→降 `cdn_mismatch`；
  ★兩者**只動信心、不動位址**。
- **FR-007**: 信心等級 MUST 為七態、入庫與線上契約皆用小寫底線字面：`cdn_verified`／
  `proxy_clean`／`direct`／`cdn_anchored`／`proxy_soft`／`cdn_mismatch`／`fallback`。前一刀的
  單一字面 `nginx_peer` 自此**退役**（其常數與型別位由七態表取代）。
- **FR-008**: 還原結果 MUST 於注入請求上下文**之前**正規化（IPv4-mapped IPv6 折為 v4），使
  存取判定／來源維計數／稽核落列／防自鎖**全下游拿到同一形**——否則同一使用者在稽核與計數桶
  中分裂為兩個身分、且閘門對 mapped 形漏判。
- **FR-009**: 轉發鏈正規化 MUST 依固定兩步（Clarify 定案、沿前代已驗證語意）：①**右端取窗**
  ——由右往左取至多固定數量的非空欄位、丟棄左端溢出（方向不可反：反向即開出「左端洪泛把真實
  來源推出視窗」的攻擊面；取窗先於解析亦把解析成本上界鎖死，洪泛不放大成本）②**逐欄正規化**
  ——剝連接埠、剝 IPv6 區域識別、剝方括號包裹；仍無法解析為位址者**丟棄**、永不當機。
  ★丟棄語意＝「該跳不存在」，鏈的相對次序不受影響——此為**安全性要求而非實作偏好**：若改採
  「遇不可解析即中止整條鏈」，攻擊者插入單一垃圾字串即可讓任意拓樸退化並操縱錨的左鄰；若改採
  「保留為佔位跳」，該佔位跳會參與硬化檢查（FR-005）與最右非受信判定，等於讓攻擊者以垃圾字串
  直接操縱判定結果。三種語意 MUST 有區辨性測試（同一輸入在另兩種語意下結論不同）。
- **FR-010**: 信任模型 MUST 於啟動時一次載入、之後唯讀共享；**預設全空＝全直連**（無隱含寬鬆
  預設）。失敗語意三層、**一律不當機且必發結構化告警**：設定檔缺席→沿用扁平環境變數退路／
  設定整體損壞→**全空**（★**不**套用退路：設定存在但壞掉時不得擴大信任）／單一集合含無效
  網段→**只清空該集合**（只縮小信任）。
  ★**開發環境 MUST 交付並掛載一份最小信任模型設定**（Clarify 定案）：僅把反向代理容器所在
  網段列入內網預設集、其餘集合留空。理由是拓樸正確性——後端的傳輸層對端恆為反向代理，它若
  不在信任集則對端閘恆先觸發、第二／三層與兩層覆蓋在任何環境皆為死碼。此設定同時是 FR-043
  部署 checklist 之樣例的**活體驗證**（★rev4 藍本的樣例從未被任何環境實跑，不帶回該形）。
- **FR-011**: 請求上下文型 MUST 維持既有三欄與取值器簽名不變（前一刀寫死的交棒 seam 兌現形）
  ——變的只有 `real_ip` 的**推導方式**（改為信任錨結果之正規化字串）與 `ip_confidence` 的
  **值域**（單字面→七態）；轉發鏈原文欄維持原樣淨化轉錄（零控制字元、長度上限）、欄位私有與
  其編譯期守門一併保留；請求路徑改由請求層注入取得。
  ★連帶 MUST 於 spec 記錄兩項消費面可見變化：①前一刀「原樣轉錄之合法性外包給資料庫型別」的
  論證**不再承重**（還原產出為位址型、正規化字串恆合法；轉發鏈解析屬**另一條軌**、與稽核轉錄
  軌並存互不影響）②「來源位址缺席→空字串→資料庫擋下」路徑消失（對端恆有值）。
- **FR-012**: 稽核表既有的**對端位址欄** MUST 開始寫入傳輸層對端（此前恆空），使鑑識三欄
  （對端位址／真實位址／信心等級）齊活——「錨怎麼推的」在事後可被獨立複驗。

**IP 存取閘（US2）**

- **FR-013**: 閘門判定 MUST 依固定六步序：①健康／觀測端點放行 ②請求上下文缺席放行
  ③結構性豁免網段放行 ④命中放行規則放行 ⑤命中阻擋規則拒絕 ⑥其餘放行。
- **FR-014**: 規則集 MUST 為 **any-match 集合語意**——白＞黑＞預設放行，**無順序化規則鏈、
  無優先權欄位**；判定與載入順序無關。
- **FR-015**: 結構性豁免 MUST 涵蓋本機與私有網段（v4／v6），且**只豁免「阻擋」、不豁免來源維
  節流**（FR-029）。
- **FR-016**: 真相分層 MUST 為「資料庫規則表＝真相、記憶體判定面＝每請求零資料庫零快取查詢」；
  真相暫不可讀時判定面 MUST **沿用上一份已知良好規則集**、不清空；啟動時初載失敗→空集放行。
- **FR-017**: 規則變更 MUST 於**無需重啟**下生效：寫端於成功寫入後重載並廣播失效通知，讀端
  以獨立訂閱連線接收並換版。通知管道故障 MUST 走放行方向並告警。
- **FR-018**: 阻擋回應 MUST 復用既有碼表之權限不足碼（`5003`／HTTP 403），**不新增碼**；每次
  阻擋 MUST 留下帶結構化欄位的可觀測紀錄（含命中的網段）。

**IP 規則管理端點（US3 後端）**

- **FR-019**: 清單端點 MUST 支援分頁與三個可空篩選（網段模糊、類型等值、刪除狀態三態），
  回應為既有分頁形；列資料 MUST 含審計軌跡（建檔／異動時間與操作者名，查無操作者→空值），
  並以布林欄標示是否位於回收桶（★刪除時間與刪除者**不上線上契約**）。
- **FR-020**: 新增與更新 MUST 於寫入前守門：①類型二值封閉（放行／阻擋），逾此→業務錯誤
  ②網段字面解析並**正規化主機位元**後才落庫，解析失敗→業務錯誤（寫前拒、零寫入）。
  唯一性衝突 MUST 映為**業務錯誤**（★MUST NOT 為伺服器錯誤）。
- **FR-021**: 刪除為**軟刪**、復原將其還原為有效；唯一性只約束有效列（同網段＋類型於軟刪後
  可重建）。對不存在／狀態不符的標的 MUST 回業務錯誤。
- **FR-022**: ★**防自鎖 MUST 為本刀唯一的 fail-closed 例外**：任何寫端動作（新增／更新／刪除

  逐列比對（以「往規則表塞列→閘紅」證明未被順手收窄）；★路由產物**四檔**的**重算冪等檢查**
  成立（重跑外掛零差異；並以「手改其中一行→檢查轉紅」證明非 vacuous），且該檢查 MUST 併
  斷言「§III.2 該軌道列所列生成檔集＝外掛實際產出檔集」（漏列一支即紅——生成檔既受 fork-delta
  全域豁免，冪等檢查就是它們唯一的機器守，清單漏列＝該支完全無守）。
- **SC-012**: 交付鏈全綠——後端測試全數通過（容器內、單執行緒）；前端型別檢查通過；
  fork-delta 檢查通過；三閘綠；手動端到端走查通過（入口 `http://127.0.0.1:22080`）。
- **SC-013**: ★**開發環境端到端可驗性成立**（Clarify 定案之驗收面）——經反向代理帶構造轉發
  標頭模擬兩個不同的公網來源，四項逐一通過：①兩來源各自失敗登入，來源維計數**互相隔離**
  ②對其中一個模擬來源建立阻擋規則，該來源即得阻擋回應、另一來源不受影響 ③對涵蓋模擬來源
  的範圍建規則時，若該來源即操作者當下來源則觸發防自鎖拒寫 ④稽核列的真實來源與信心欄為
  **推導真值**（非反向代理自身位址、非單一常數）。★此四項在無信任模型設定時結構性不可驗
  ——本條即該設定存在的驗收證據。

## Assumptions

- **信任模型設定源沿前代全形**（工程自決、報備）：以環境變數指向的設定檔宣告六個集合，
  啟動時一次載入。★**開發環境掛載一份最小設定**（Clarify 定案、FR-010 後段）——僅列入反向
  代理容器網段，CDN／通道／公開出口等集合一律留空。連帶已知態：不帶構造轉發標頭的瀏覽器
  流量，其真實來源仍收斂為同一位址、共用單一來源桶，走查時容易誤觸鎖定（以解鎖端點自癒）。
- **信心字面退役方式**（工程自決、報備）：既有的單一字面常數由七態表取代；因該欄無 CHECK
  約束，此變更**零 migration**；既有寫入點（登入稽核三處落列）**零改動**，值隨還原升級自動
  變化——這正是交棒 seam 承諾的驗證點。
- **解鎖端點為 API-only**（工程自決、報備）：解鎖按鈕的歸屬頁面是使用者管理頁（尚未建立），
  故本刀不建 UI 按鈕、不建前端請求包裝；「端點已備、按鈕待使用者管理刀」列為已知態（FR-044）。
  按鈕權限碼 `user:unlock` 已在 seed、屆時零 seed 改動即可接線。
- **稽核覆蓋不對稱屬刻意的最小改動**（FR-032）：既有設定寫端維持不落操作稽核列（前一刀的
  刻意決定），本刀只為**新端點**落列、不回改既有端點。此不對稱於收刀登記帳面，由稽核域刀
  統一收斂。
- **操作稽核落列與生效的次序**：純資料庫路徑（IP 規則四個寫端）以同交易保證原子；跨資料庫與
  快取的路徑（解鎖）採「稽核先於生效」（FR-031）——因快取不參與交易，唯有先寫稽核才能使
  「生效但零稽核」在構造上不可達。
- **規則管理契約沿前代最小誠實形**：清單三個篩選、審計欄上線上契約（建檔／異動時間與操作者名）、
  刪除時間與刪除者不上契約（布林欄已足以辨識回收桶）；識別碼序列化沿既有預設（數值形＋
  安全上界守衛）。
- **前端語言面不擴**：沿用既有兩語 runtime locale；治理錨點檔只承載後端訊息鍵（FR-036）。
- **實作紀律引用**（非本 spec 新拍板）：rev4 對應碼先讀後寫、重打字消化、註解一律重寫
  （憲法 §I.5＋ADR 0019，rev4 樹唯讀）；rust build／test 容器內全程 serial；前端驗收走
  CDP 三方對照（rev5 與 rev4 同頁）。
- **編排紀律引用**：TDD 期以 Workflow 編排並遵防呆六件套；★已知態——改動編排腳本後以 resume
  續跑會使看門狗上限推導沿用舊快照，故需某階段重跑一律**新開單階段 workflow**。
- **stakeholder 判定承前例**：本刀 stakeholder＝admin 後台的超級管理員、稽核者與 workspace
  維護者；spec 中的端點路徑／碼／政策座標／軌道名／閘名稱係**交付物座標（WHAT）**，非實作
  技術選型（HOW）。

### Out of Scope

- **通用化節流 seam**（B-020 另一半）：本刀只交付來源維本體，「可掛任意敏感端點的通用 seam」
  待第二個消費者存在（＝改密端點）時再做——現在通用化等於為單一消費者設計抽象。
- **改密端點舊密節流**（B-021）：其前置不是節流技術而是「改密端點得先存在」，屬使用者中心域。
- **稽核管理頁與其查詢端點、政策歸檔頁**（B-008 其餘部分）：本刀只解 IP 規則頁一張；稽核頁
  所需的查詢端點不在本刀。連帶：**轉發鏈欄的渲染端轉義**（B-072）本刀只建防線與機器守、
  不宣稱關帳（FR-038）。
- **地理區欄**：資料檔與查詢元件整包不搬，該欄維持恆空（既有 prod 遞延決策第 2 款）。
- **存取軌跡 middleware**：屬稽核域射程，本刀不建。
- **prod 資產**：既有「prod 不入 roadmap」決策持續有效——本刀交付的是**部署 checklist 文件**，
  不是 prod 配置檔；CDN 邊緣網段清單維持空集（開發環境恆不生效）。
- **快取持久化模式變更**：重評結論為**維持現狀不開**（暴險受「狀態即權威」封頂：判定面不依賴
  快取、解鎖標記遺失可再解鎖自癒），結論落已知態紀錄（FR-044）。
- **列表欄位排序能力**（B-027）：前代同頁已判「後端預設排序已足」，本刀不觸發。
- **前端 demo 資產去留**（B-018）：本刀不動 demo 面。
- **線上契約裁判面的嚴格模式**：快照全域未開「禁止額外欄位」＝已知態；本刀重評結論為**不動**
  （動快照生成器會牽動既有全部路由的裁判行為、屬 wire 地基面），只更新警示句。
