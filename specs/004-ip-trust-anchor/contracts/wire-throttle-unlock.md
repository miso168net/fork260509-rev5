# Contract — 管理員解鎖端點

> 一條 route、政策保護；casbin 政策列（`/systemManage/unlockLogin` POST）與按鈕權限碼
> `user:unlock` **皆已在 001 凍結 seed**（research R9-1 逐列複核）⇒ 零 seed 變更。
> ★本刀 **API-only**：解鎖按鈕的歸屬頁面是使用者管理頁（尚未建立），故不建前端請求包裝
> （spec FR-035、已知態 FR-044）。

## `POST /systemManage/unlockLogin`

**Req**（camelCase；★兩維至少擇一）

| 欄 | 型 | 語意 |
|---|---|---|
| `dimension` | string | `user`｜`ip` |
| `userName` | string \| null | 維度為 `user` 時必給 |
| `target` | string \| null | 維度為 `ip` 時必給——**位址字面**，由後端經計數桶粒度導出（v4 `/32`、v6 `/64`、IPv4-mapped 先折 v4） |

**處理序**（★次序即契約，見 data-model §1.3）

1. **維度解析＋標的導出**——畸形（維度不明／位址不可解析／該維必填欄缺席）→
   `2222 biz.throttle.invalidUnlockTarget`；★此步**先於**任何稽核與狀態變更，
   故畸形請求**零稽核列、零狀態變更**。
2. **★先寫操作稽核列**（純資料庫單寫）——寫入失敗 → `5000` **中止**，快取**一概不動**
   （標記未寫、鎖未刪）⇒「已生效但零稽核列」構造上不可達。
3. 寫解鎖標記＋清除該維鎖定鍵。

**標記值格式（★契約）**：**unix 秒的十進位字串**。讀端不可解析時視為無標記
（良性方向：至多少解鎖一次，絕不誤放行）。

**200**：`{ code: "0000", msg: "common.success", data: null }`

**錯誤**

| 情境 | 碼 | msg key |
|---|---|---|
| 參數畸形 | `2222` | `biz.throttle.invalidUnlockTarget` |
| 非超管 | `5003` | `system.forbidden` |
| 稽核寫入失敗／內部異常 | `5000` | `system.internal` |

**冪等**：對未被鎖定的標的解鎖 → `0000`（no-op 語意；★不得以異碼洩漏「該標的是否正被鎖定」）。

## 帳號維的三件補齊（既有讀端零改動）

前一刀已把帳號維計數下界的解鎖標記**參數位預留**在查詢形內（無標記綁 SQL NULL、
`GREATEST` 非 strict 自然退化）。本刀補齊的恰三件：

1. 標記鍵（帳號維鍵形）
2. 讀取端（把標記值餵進計數下界）
3. 計數標籤（觀測面維度標示）

★節流查詢函式本體**零改動**——這是前一刀交棒時明文預留的形。
